# BC best starts PPO with a fresh critic head

Phase 6.2 starts PPO from the [[top-1-team-bc-checkpoint-is-selected-by-held-out-nll-only|top-1 team BC best]]. This change checks that the checkpoint loads through `run_ppo`'s fresh-launch path and decides what PPO does with the BC critic. It adds one load mode for that decision. Working evidence: `ops/rebuild-2026-09-29/bc-handoff/`.

## The load

- The BC run's PPO config `configs/kaggriculture_1gpu_eager.yaml`, `configs/kaggriculture_2rank.yaml`, `configs/kaggriculture_4rank.yaml` and the integration branch's `configs/kaggriculture_8rank.yaml` have equal `model`, `obs_spec` and `action_spec` sections. The 8-rank file was checked at `kg/isaiah-gap-closure` `faed717` and `5b43062`. `force_flash_attn` has to be false for a CPU forward. It selects a kernel and changes no parameter.
- The real checkpoint (SHA-256 checked against the pod and its record) loads through `PPOTrainer.load_model_weights`, the call `run_ppo` makes on a fresh launch. The eager, 2-rank and 8-rank models then give equal values, winner probabilities and log-probs on rows of a real validation shard. The outputs are finite, and the policy-seat turn NLL on those rows is 0.419.
- Prohibited state. Unknown model tensors (for example an `opponent_embedding.weight`) were already rejected by `load_model_state_dict_allowing_lora`, on every loader. `run_ppo._checkpoint_metadata`, used by the resume last-best loader, also rejected unknown top-level keys. `PPOTrainer.load_model_weights` and `load_checkpoint` did not: they read the keys they knew and ignored others, such as `opponent_id` or `hidden_state`. Neither did `run_ppo._load_model_weights`, the `teacher_init` and initial last-best loader (Codex verification r1, P2). `ppo.reject_unknown_checkpoint_keys` now rejects any key that `write_checkpoint` does not save. `ppo._checkpoint_metadata` and `run_ppo._load_model_weights` both call it. Isaiah's minimal model-weights checkpoints, which have no optimizer keys, still load.

## The critic decision

**Evidence.** All 523 BC episodes are wins for the imitated seat: the manifest has one policy seat per episode, and its final bank is always the larger. BC's winner cross-entropy therefore always labelled the imitated seat the winner. On one held-out game (360 turn rows, 720 seat values), 700 seat values (97.2 %) have |value| > 1 − 2e-6, and both seats do on 345 of 360 turns (95.8 %). The values are already −1 and +1 at turn 20 of 720. PPO trains the Kaggriculture critic with an MSE loss on value 2p − 1, which config requires. That value's gradient through the softmax scales with p(1 − p). With each model's target set to the opposite sign of its own prediction, the critic-head gradient norm was 0.118 with the BC head and 12.4 with a fresh head. It is a hypothesis, not measured, that the BC critic detects the imitated team's seat from the observation. If it does, that seat does not exist in self-play, where both seats run the same policy.

**Isaiah.** Isaiah had no BC-to-PPO path, so there is no precedent for what it would do with the value head: "I stuck with pure self-play reinforcement learning and avoided any sort of imitation learning initialization" (`docs/write-up.md`). His warm starts ("occasional warm restarts", and `--load-model-weights`) load the whole `checkpoint["model"]`. Their only variant loads optimizer state too (`model_and_optimizer`). Those checkpoints came from his own PPO, so their critic had been trained on the same self-play winner target. His source does treat the critic head as its own unit. `reset_parameters` gives `critic_head.out` its own init gain, and LoRA's `target_value_head` adapts it separately. `critic_mode`/`value_mode` define its target as the self-play winner probability.

**Choice.** This is an implementer choice under [[../decisions/recipe-choices-align-to-isaiah-without-owner-escalation|the recipe-choices Decision]]. Keep Isaiah's whole-model load for everything the BC target shares with PPO: the trunk, the actor and the critic value tokens. The value tokens are trunk inputs that the other tokens attend to, so they stay. Start the critic head from Isaiah's own fresh initialization, so that PPO learns the critic under Isaiah's self-play winner semantics. Keeping the whole critic would carry over the selection-biased, saturated target. A policy-only warm start is the same thing in this shared-trunk model. On the real checkpoint the fresh head leaves the actor's log-probs bit-identical. No row saturates, and the mean |value| is 0.468.

## Adaptation inventory

- `scripts/run_ppo.py`: `--load-model-weights-mode model_fresh_critic_head` and `_fresh_state_keys_for_mode`. This mode supports `KaggricultureTransformer` only and raises otherwise. The optimizer and scheduler start fresh, as in `model_only`.
- `python/owl/train/ppo.py`: `load_model_weights(..., fresh_state_keys=...)` still validates the checkpoint's full model state. It then restores the named tensors to their values before the load, which is the fresh launch's `reset_parameters` state. Under DDP that state is rank 0's, because the adapter's `DistributedDataParallel` broadcasts parameters at construction (PyTorch default; not run here). `reject_unknown_checkpoint_keys` rejects unknown top-level keys; `_checkpoint_metadata` and `run_ppo._load_model_weights` call it.
- Tests: `tests/kaggriculture/test_bc.py` adds the handoff tests. They check config equality, and the three modes × every ranked config on a checkpoint written by the BC trainer's own `_save_best`: equal outputs, fresh critic tensors, optimizer state only with `model_and_optimizer`. They also check prohibited-state rejection on the `PPOTrainer`, resume-metadata and `teacher_init` loaders (a minimal `{"model": ...}` checkpoint still loads), mode guards, and an opt-in real-checkpoint test (`KG_V3_BC_BEST`, `KG_V3_BC_SHARDS`). The fake trainers in `tests/scripts/test_run_ppo.py` and `tests/kaggriculture/test_teacher.py` accept the new keyword. `README.md` documents the mode and the BC launch. Two pre-existing docstrings in `bc.py` and `bc_data.py` were reflowed for ruff D205/D209.

Phase 6.2 launch: `torchrun --nproc-per-node 2 scripts/run_ppo.py configs/kaggriculture_2rank.yaml runs --load-model-weights <run>/checkpoint_bc_best.pt --load-model-weights-mode model_fresh_critic_head`. With `teacher_mode: last_best` and no `teacher_init`, the initial last-best teacher is copied from the loaded model. So its value distillation (coefficient 0.005) starts against the fresh head until the first promotion.

## Checks and limits

- The 14 targeted tests passed with the real checkpoint and shard present. `uvx --from rust-just just py-prepare` ran 2,193 passed, 12 skipped, with docs fresh.
- `run_ppo` still stops before the environment for Kaggriculture (Task 3.1), so `main` was not run. The tests call the function its fresh-launch branch calls. No PPO update has run from this checkpoint. That the fresh head learns better than the BC head is inferred from the gradient probe, not measured.
- The saturation figure comes from one validation game, not the corpus. The integration branch now builds the actor from native grammar tables. Those are non-persistent buffers, so the checkpoint keys do not change, but the load was not rerun on that tree.
- Reopen this choice if a PPO run from the BC best shows the fresh critic's early explained variance or value loss behaving worse than a comparison start, or if BC data ever include losses and draws.
