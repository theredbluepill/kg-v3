# Kaggriculture configs follow Isaiah's scaling_6m recipe

These configs **deliberately align to Isaiah**, as the [[../decisions/recipe-choices-align-to-isaiah-without-owner-escalation|recipe Decision]] requires: every recipe choice resolves toward upstream `scaling_6m`, and only per-rank shapes change with the world size.

## What changed (rebuild Task 3.4)

- **`configs/kaggriculture_2rank.yaml`** (128 envs/rank, `segments_per_minibatch` 8, accumulation 1) **`configs/kaggriculture_4rank.yaml`** (64/4/1) and **`configs/kaggriculture_8rank.yaml`** (32/2/1, added 2026-09-29 for the owner's likely 8-rank main run; see the [[../decisions/start-multi-gpu-qualification-with-two-ranks|multi-GPU Decision]]). This is Isaiah's 6M multi-GPU division from `winner_ce_6m_4x5090.yaml` (his per-rank fit of the different `winner_ce_6m` recipe): divide `n_envs` and `segments_per_minibatch` by the world size and keep the global batch. His only 8-GPU config, `scaling_50m`, keeps 256 envs/rank instead, so it is not the precedent for a 6M global workload. Everything else is `scaling_6m`'s:
  - the Muon optimizer and the linear-warmup cosine schedule (1,000 / 400,000 steps; the global batch is unchanged, so nothing is rescaled);
  - the PPO coefficients (gamma 1, λ 0.9, clip 0.2, no value clip, `vf_coef` 2, `ent_coef` 1e-6, grad norm 10, `target_kl: null`, `per_player`, normalized advantages);
  - the last-best teacher (0.005 / 0.005, `teacher_segments_per_minibatch` 128, not divided, as in Isaiah's per-rank configs), 8 evaluation replays, `compile_mode: default`, BF16, the trunk-compile defaults and the 20M checkpoint cadence.
- **Kaggriculture-only settings:** the env section (`obs_spec` schema 3, `hire_limit` 241, `reward_mode: win_loss`, and a provisional `native_threads: 2` that Task 6.1 measures) and the owner's economic shaping 0.2. The other reward coefficients are the reference branch's defaults, named as in its `rewards.py`, which plan C8 ports. The model is the existing `configs/model/kaggriculture.yaml`, which already forces FlashAttention. It is not renamed to the plan's `kaggriculture_gpu.yaml`, because model tests and docs cite that path.
- **Local CPU configs:** `configs/kaggriculture.yaml` (2 envs, spm 1, FP32, no compilation, no replays) and the tiny `configs/model/kaggriculture_cpu.yaml` (width 16, depth 1, FlashAttention off) are for Task 3.5. They use the same optimizer and PPO coefficients.
- **Startup workload check** (`python/owl/model/kaggriculture_workload.py`, from the GEMM-limit audit in the [[compiled-gemm-template-overflows-above-2-21-rows|overflow Reference]]):
  - `ppo_forward_workloads` derives each forward's per-rank seat rows: rollout `n_envs × 2`, minibatch `spm × horizon × 2`, teacher chunk `min(teacher_spm, n_envs) × horizon × 2`, and evaluation `n_envs × 2`. A BC caller adds its own `ForwardWorkload`.
  - `check_workload_headroom` divides these by the model's own `rows_per_chunk` (709 padded tokens × width 512, giving 5,915 rows) and `head_rows_per_chunk` (11,096). It raises when one row cannot fit either limit or a workload is empty. Head calls are exact. Trunk figures assume full padding, so trunk calls are an **upper bound** and trunk headroom a **lower bound**: the packed path plans chunks from actual token counts (16,384 rows of 300 tokens need 2 packed chunks, not 3).
  - **At startup:** `scripts/run_ppo.py` calls `_check_model_workload` once the per-rank shapes are final (after runtime-GPU adaptation, fresh or resume) and before the run directory, env or model exist. The teacher chunk is omitted when `teacher_mode` is unset. The main process prints one `GEMM workload headroom …` line per workload. Isaiah's Orbit models do not chunk, so they are skipped.
- **Kaggriculture env in `FullConfig`** (Codex r2 P1):
  - `python/owl/kaggriculture/config.py` adds `KaggricultureEnvConfig` (`n_envs`, the Kaggriculture obs/action specs, `reward_mode: win_loss` only, `reward_shaping`, `pin_memory`, `native_threads ≥ 1`; Isaiah's `two_player_weight` is an unknown key) and `KaggricultureRewardConfig`. The reward config keeps the reference branch's field names and defaults (including `econ_ineffective_cap` 0.1), its `terminal_scale`, and both of its budget checks: the active caps must sum below one, and positive `econ_shaping` needs a positive starvation or drought weight.
  - `python/owl/train/config.py`: `FullConfig.env` is `GameEnvConfig`, Isaiah's `EnvConfig` or `KaggricultureEnvConfig`, chosen by a callable discriminator on `env.obs_spec.obs_spec` (absent means Orbit, since Isaiah's `EnvConfig` has no game tag). The validator pairs the Kaggriculture env and model in both directions, requires `rl.gamma=1.0` and rejects `value_loss: winner_ce` for Kaggriculture (after the integration merge it then applies Tasks 3.2/3.3's `_validate_kaggriculture_training`, which adds `value_loss: mse` and `ppo_clip_mode: per_player`; see the [[evaluation-and-truncation-follow-the-kaggriculture-objective|evaluation and truncation Reference]]), and runs Isaiah's Orbit cross-checks unchanged in `_validate_orbit_constraints`. This replaces the Task 3.1 model-side rejection.
  - `require_orbit_env(env, context=...)` narrows to `EnvConfig` and raises an explicit `RuntimeError` for Kaggriculture. `scripts/run_ppo.py` calls it right after the workload check (so a Kaggriculture launch stops before the run directory exists) and at its other Orbit-only sites (model build, teacher specs, evaluation env); `scripts/benchmark_checkpoints.py` uses it through a `LoadedCheckpoint.env` property and at checkpoint load.
- **Tests:** `tests/scripts/test_run_ppo.py` drives `run_ppo.main` from the shipped YAML through the real `FullConfig.from_file`; only the release-build check, torch setup and the distributed session are stubbed, and the run-dir, env and model steps are fail-if-reached sentinels. A `-o model.embed_dim=2097152 model.n_heads=65536` override fails the check with no headroom lines and no run directory. The 2-, 4- and 8-rank configs print the headroom lines and then stop with the explicit not-wired error, with no run directory. A real resume directory saved at 2 ranks and resumed on 1 checks the adapted 512 rollout rows. `tests/owl/train/test_config.py` again loads every `configs/*.yaml`, as in Isaiah's tree.

## Limits and handoffs

- **Launch stops after the check.** The configs load and pass the workload check, but `run_ppo` has no Kaggriculture environment until the native env binding (Task 1.4) and the trainer game seam (rollout storage and observation mapping, Task 3.1) land. Replace `require_orbit_env` at those sites with the game's env and model paths then. The env and reward schema is validated, not executed: no reward is computed from it yet.
- **BC is not checked.** The BC trainer (Task 5.2) does not exist yet; it must add its batch as a `ForwardWorkload` through the same check.
- **The trunk bounds are conservative.** Trunk headroom is a lower bound and trunk calls an upper bound, from full padding. Evaluation uses the `n_envs × 2` upper bound.
- **Chunking is only CPU-tested.** Teacher chunks rely on the model's chunking, which has not been measured on the GPU.
- **Pending dependencies:** `eval_replay_games: 8` needs Task 7.3's Kaggriculture replay export, and the last-best teacher needs Phase 4.
- **Memory is unmeasured.** The spm 8 / accumulation 1 split holds only if the Task 6.1 memory smoke confirms it; otherwise the plan moves to 4 / 2 with the same product. The 8-rank shape (32 envs, spm 2) is qualified only by Task 6.3b on an owner-approved 8-GPU pod.
