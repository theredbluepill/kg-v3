# Kaggriculture BC trainer warm-starts PPO from the held-out best

Plan Task 5.2 asks for a BC trainer on the rebuilt model that reuses Isaiah's optimizer factory, BF16 and compile path, keeps the best checkpoint by held-out NLL and stops on sustained held-out degradation (lesson L9). This change builds the trainer script and its tests. The BC run itself waited for the Task 5.1 shards and the pod; the one run so far is recorded in the [[top-1-team-bc-checkpoint-is-selected-by-held-out-nll-only|top-1 team BC checkpoint Reference]].

## Adaptation inventory

- `scripts/train_bc.py`: CLI in `run_ppo.py`'s shape (fresh `CONFIG --data --output-dir`, restart from a run directory, `torchrun` for several GPUs, `--log-mode`, `--wandb-mode online|offline`, `--max-runtime-hours`, `--source-commit` on a fresh launch or a restart). Each launch or restart appends an attempt record to `bc_attempts.jsonl` (see "Restart identity" below). It runs the GEMM workload check for the BC microbatch and validation forwards and the compile-stack check. It then builds the model with `create_model` and `reset_parameters`, compiles through `configure_model_compile` (the Kaggriculture cuBLAS-only claim), builds the optimizer with `create_optimizer` / `create_lr_scheduler` and wraps it with Isaiah's DDP adapter.
- `python/owl/train/bc.py`: `BCConfig`, the objective, `TrainSharding`, `HeldOutSelection`, checkpoint and resume state, `bc_config_sha256` and `train_bc`. Since `kg/rebuild-bc-wandb` its W&B logger is the shared `create_metric_logger` (project `kg-v3`, job type `bc`), with the credential gate and receipts of the [[v3-launchers-fail-fast-without-wandb-credentials|credential gate Reference]]. BF16 comes from the PPO config's `rl.dtype` through `autocast_context`. The model, dtype and compile settings come from the PPO config that BC warm-starts (`ppo_config`), so the BC checkpoint matches that PPO run's model. `wrap_bc_model_for_distributed` casts the model for Isaiah's Orbit-annotated DDP adapter, whose dispatch passes Kaggriculture batches through unchanged. The Task 3.1 trainer seam has not generalized those annotations yet.
- `python/owl/kaggriculture/bc_data.py`: the shard writer and loader. `configs/bc/kaggriculture_2rank.yaml`: the 2-rank BC config for `configs/kaggriculture_2rank.yaml`. It sits under `configs/bc/` because the existing config tests load every top-level `configs/*.yaml` as a PPO `FullConfig`. `README.md` has a new "Kaggriculture BC warm start" section.

## Decisions made here

- **The critic is trained, not frozen.** Isaiah trains all of the shared trunk and both heads together, and his teacher distillation weights policy KL and winner CE equally (`teacher_kl_coef = teacher_value_coef`). BC is distillation from the recorded player. So the loss is the turn NLL divided by program length, plus `value_coef` (1.0) times the per-seat winner CE against the episode's raw final banks (L1: the larger bank wins, a draw is 0.5 each). The reference froze the critic head, but its trunk still moved, so its critic reached PPO miscalibrated with no target. A test shows that a policy-only loss leaves the four `critic_head` tensors without gradients. Isaiah's adapter builds DDP without unused-parameter detection for this model, so the joint loss also gives every parameter a gradient. DDP itself was not run. Isaiah's own recipe used no imitation learning (`docs/write-up.md`); BC here is the plan's owner-required addition. Because the BC data hold only the imitated seat's wins, PPO starts from the BC best with a fresh critic head ([[bc-best-starts-ppo-with-a-fresh-critic-head|handoff Reference]]).
- **Shard format.** The loader follows the refreshed 5.1 brief (branch `kg/rebuild-bc-brief` at `bcefd02`, still awaiting Codex review). Shards are `kaggriculture-bc-shard-v1`: one `np.savez_compressed` per episode at `<split>/<day>-<episode_id>.npz`, with the 28 observation fields, `can_act`, `tokens`, `lengths`, `turn` and a `schema` id. The brief lists the manifest's contents but not its key names. The loader requires `schema`, `observation_schema_version`, `contract_document_version` and per-episode `episode_id`, `split`, `terminal_banks`, `admitted`, `shard_path`, `shard_sha256` and `shard_bytes`. It keeps other custody keys uninterpreted. Task 5.1's `prepare.py` must emit these names, or use `write_bc_episode` / `write_bc_manifest`.
- **Residency and sharding.** Each rank keeps rows `[rank::world_size]` of every episode in host memory (the reference's split). Exact integers are stored as range-checked int32 and tokens as int16, then gathered back as int64. Loading verifies every shard's SHA-256, byte count and schema id, and runs the full `check_contract` once. Training order is a permutation seeded by `(seed, epoch, rank)` over that rank's rows, so restarting from `bc_state.pt` under the same source and settings repeats the uninterrupted run's rows, updates, evaluation steps and stopping step on a deterministic device (the kept checkpoint can differ; see "Selection and stopping"). Every evaluation covers all validation rows. A preflight pass admits every training program through `evaluate_actions` before step 1.
- **Selection and stopping.** Each evaluation's held-out NLL feeds `HeldOutSelection`, which keeps selection and patience apart. Every strict new minimum is written as `checkpoint_bc_best.pt`, with a SHA-256 record in `checkpoint_bc_best.json`. Patience counts evaluations since the last improvement of more than `min_delta` over the previous such improvement, so gains inside `min_delta` still replace the best checkpoint but do not reset the count (the early-stopping convention; the first version gated the checkpoint by `min_delta` too, which Codex verification r1 showed could discard the lowest NLL). Training stops when that count reaches `patience_evals`, at `max_steps` or at the runtime cap. Patience counts scheduled evaluations only. A budget or runtime stop between them evaluates the final weights once (`bc/scheduled_evaluation` 0 in `bc_history.jsonl`); that evaluation can replace the best checkpoint but leaves the patience count alone. Codex verification r2 showed that counting it let a run stopped at step 1 and extended to 4 stop at step 2, where the uninterrupted run stopped at step 4. With it excluded, the resumed run evaluates and stops at the uninterrupted steps, and its best checkpoint is the minimum over a superset of the same weights, so never higher in held-out NLL. This is a choice made here: Isaiah has no BC loop and PPO has no held-out patience rule.
- **Restart identity.** A restart is a new attempt, not a continuation of the launch's identity. `bc_attempts.jsonl` gets one record per launch or restart: attempt index, that checkout's source (`git rev-parse HEAD` with a `-dirty` suffix, or `--source-commit`), the lineage of every attempt's source, start step, the parent `bc_state.pt` SHA-256, dataset root and manifest hash, world size and start time. The best-checkpoint record and `bc_result.json` copy the attempt that wrote them. `bc_state.pt` stores the trajectory settings (the BC config except `max_steps`, and the whole PPO config by content); a restart with any other difference fails and names the changed fields, so only the step budget can grow. A changed source is recorded, not rejected: exact replay is claimed only for an unchanged source. `bc_history.jsonl` holds the NLL curve and `bc_result.json` the stopping step and reason. The best checkpoint has exactly `run_ppo.py`'s keys with `env_steps` 0, next to the PPO `config.yaml`.
- **Starting values** in `configs/bc/kaggriculture_2rank.yaml` are not measured. They are the PPO config's Muon/AdamW values with the cosine over `max_steps`, 256 turn rows per rank per step, `max_grad_norm` 10, evaluation every 200 steps and patience 10. The run statement has to name any change.

## Checks

- `tests/kaggriculture/test_bc.py` (30 tests) uses tiny CPU models and synthetic shards whose programs a second tiny model sampled. The tests cover:
  - the shard round trip at contract dtypes, and rejection of a tampered hash, a duplicate episode, an old `features/context` shard, a missing split, unpaired rows and out-of-range compaction;
  - the loss halving on a memorizable batch, and every parameter receiving a gradient;
  - a hand-computed objective oracle (per-frame probabilities, lengths and winner probabilities in, the length-normalized NLL plus CE out), and `train_bc`'s own update path moving every floating tensor and lowering the full training objective by more than 10%;
  - two fake ranks holding disjoint rows that cover each split, with deterministic per-rank order, and equal-length rank partitions drawing different permutations (so the rank is in the seed);
  - a scripted evaluator that selects the best checkpoint and stops, with the best weights equal to the step-1 snapshot; the verifier's probe (NLLs 2.0, 1.97, 2.4 with `min_delta` 0.05) keeping step 1; and a sub-`min_delta` trickle that keeps updating the best yet stops;
  - an unscheduled evaluation updating selection but not patience; a budget stop at step 1 extended to 8 stopping at step 4 like the uninterrupted run, with bit-equal weights, the same scheduled evaluations and a best no higher (the r2 probe, and a variant whose off-cadence NLL is the minimum);
  - a restart from `bc_state.pt` that matches an uninterrupted run bit for bit, and a resume that rejects a different dataset, world size, seed, batch, accumulation, `min_delta`, optimizer or PPO `rl` section while admitting a larger `max_steps`;
  - the best checkpoint loading through `run_ppo`'s `_load_model_from_checkpoint`, `_load_model_weights` and PPO's `_checkpoint_metadata`;
  - the 2-rank BC config targeting the 2-rank PPO config;
  - the script running fresh and resuming on CPU; a script restart recording attempt 1 with its own source, the parent state hash and the source lineage in `bc_result.json` and the best record; and a script restart with an edited seed failing before training; and the attempt-record guards rejecting a missing or empty file on resume, existing records on a fresh run, a wrong index, a non-object line and a missing or non-string source.

Its reported gaps for reversed loss signs and a removed real `optimizer.step()` are now killed by the r1 tests; 11 targeted mutants of the fixes, loss sign, length normalization and the real optimizer step were all killed (`ops/rebuild-2026-09-29/5.2-r1/mutations.log`). ## Limits and open dependencies

- Codex's other reported wiring gaps remain untested on CPU: removing autocast, compile, DDP, startup workload/stack checks, accumulation normalization, clipping, scheduler stepping, preflight or the runtime cap survives the suite, and several malformed shard/config guards have no negative fixture (the attempt-record guards now do).
- Nothing has run on a GPU yet: no BF16 autocast, compiled trunk, DDP/NCCL, pinned-memory transfer or live W&B. The owner's Mac ran FP32 with no compilation. Throughput, peak memory and load time are unmeasured: each rank decompresses every shard, gathers on the host each step, and `clip_grad_norm_(error_if_nonfinite=True)` syncs once per step. Host memory per rank for the real slice is unmeasured too.
- The BC run needs the 5.1 shards. Their token half waits on the Task 1.4 `kaggriculture_encode/decode` binding, and the full-slice run needs a machine that can read volume `4llk4uaf20`. It also needs the pod and FlashAttention, because `configs/model/kaggriculture.yaml` forces it (plan 6.0). Since the Phase 5 landing (`kg/merge-bc-c`) `run_ppo.py` runs Kaggriculture (Tasks 1.4/1.5/3.1 merged), but no PPO update has started from the BC best; its loaders are exercised, including on the real A100 checkpoint ([[bc-best-starts-ppo-with-a-fresh-critic-head|handoff Reference]]). `train_bc.py` now uses the integration's credential gate, shared logger and attempt receipt ([[v3-launchers-fail-fast-without-wandb-credentials|credential gate Reference]], BC adoption); no BC launch has run under it yet.
- The synthetic fixture uses one `make_obs` env per row. Multi-env `make_obs` batches with small actor counts can draw a lifespan below the −1 sentinel and fail `check_contract` (seen with 4–5 envs), which is a limit of the test fixture.
