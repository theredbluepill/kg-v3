## 3. The `agent(obs, config)` wrapper

New files (Claude stream):

- `python/kaggriculture_main.py`: the entrypoint, copied to `main.py` in the
  tarball.
- `python/owl/agent/kaggriculture_agent.py`: the agent class.
- `python/owl/kaggriculture/kaggle_view.py`: the observation and configuration
  view.

Isaiah's Orbit `Agent` stays unchanged. It is Orbit-shaped: recurrent state,
LoRA/int8 modes, `min_fleet_size`. The shared pieces move into small helpers
used by both, not copies: thread pinning, checkpoint-config loading,
`meta`-device construction plus `load_state_dict(strict=True)`, and the timing
log.

`main.py` does this at module top level (F2):

1. Set `OMP_NUM_THREADS`/`MKL_NUM_THREADS`, then `torch.set_num_threads(N)` and
   `set_num_interop_threads(1)`. N comes from the latency receipt (§7). The
   default is 1, as in Isaiah's `main.py`.
2. Import `owl` and call `owl.rs.assert_release_build()`.
3. Load `models/primary/config.yaml` and `checkpoint.pt`, and build the model on
   CPU in fp32.
   - Override **only** the runtime dispatch flag `force_flash_attn` to false. It
     is not a weight, and CUDA FlashAttention cannot run on CPU.
   - Reject any checkpoint or config carrying hidden-state or recurrent keys, per
     the [stateless constraints](../../../cookbook/decisions/the-policy-is-stateless-and-observation-only.md).
   - Call `model.eval()`.
   - Run one warm-up forward on a bundled fixture observation, so turn 0 pays
     the warm-up once and inside the 60 s bank.
4. Define `agent(obs, config)` last (F3).

`agent(obs, config)` runs under `torch.inference_mode()`:

1. **View.** Build `view = {"step","day","hour","farms","market","town"}` from
   `obs`, the own `private`, `seat = obs["player"]`, and a game configuration.
   - The configuration keeps the keys of the pinned `kaggriculture.json`
     `configuration` block plus the framework keys `actTimeout`, `runTimeout`
     and `seed`. It drops `__raw_path__` (F4) and any other key, logging each
     dropped name once.
   - Use explicit key reads (no `getattr`) and `json.dumps` without
     `sort_keys` (F9).
   - `remainingOverageTime`, `player` and any seed never reach the model. Seat
     only selects which row is written.
2. **Encode** with the Rust seat binding (§4) into a preallocated `[1,1,…]`
   `KaggricultureObsBatch` of CPU tensors (allocated once and reused).
3. **Forward.** Call `model(obs_batch, deterministic=True)`. Greedy decoding is
   Isaiah's packaged default (`agent_config.yaml: deterministic: true`). A
   sampled mode is an explicit config switch, never a silent default.
4. **Decode.** Call native `kaggriculture_decode(tokens[0,0], length, actors,
   order_limit, hire_limit=241)` from Task 1.4. The actor count comes from the
   own `actor_mask[..., :241]` and the order limit from `order_limits`, as
   `briefs/1.5.md:231` requires. Return the parsed dict: `farmer`, `hands`,
   `market`, in canonical form.
5. **Log.** Print one compact line per turn: step, encode/forward/decode ms,
   remaining overage, action length. Kaggle keeps 10k characters per step.

No state carries between turns except the loaded weights and the reusable
buffers. The buffers are fully overwritten each turn; a test asserts that
poisoning them before a call leaves the output unchanged.

## 4. Encoder: same Rust code as training, not a Python fallback

The existing binding needs both seats' private state (full `TraceHeader`). A
live agent sees only its own. The native env and BC preparation have both.

Add `encode_kaggriculture_seat_into(view_json: str, seat: int, *, <the 29
named buffers with leading shape [1,1]>)`. It must be:

- in `src/kaggriculture/mod.rs`, validated through the same `ObservationConfig`
  and public-context checks;
- written through **the same `write_seat`** that `write_env` calls;
- given a shape-valid empty rival private (an empty map per rival actor, empty
  shed and seeds). Contract principle 1 says the rival's private state never
  reaches the own row, and a test proves it (T1).

A Python encoder that reproduces the tensors is **rejected as the plan**. It
would be a second implementation of every contract channel, including float32
scaling and rank semantics. The rebuild removed exactly that duplication
(plan C4/C6). It is reopened only if §6 proves the extension cannot load on
Kaggle. Even then it must pass the same byte-identity corpus as T1, and the
owner is told.

## 5. Error boundary (a deliberate exception to fail-fast)

An exception inside `agent()` loses the game (F5). So `agent()` catches
`Exception`, prints the traceback with its step, increments a module counter,
and returns the default action F6. This matches Isaiah's `b7185e5`.

Qualification must never hide an error behind this guard. Every test,
benchmark and the local episode run with `KAGGRICULTURE_AGENT_STRICT=1`, which
re-raises. A qualifying run must also report `caught_errors == 0`. Kaggle does
not set the variable. Import-time failures (missing `.so`, bad checkpoint) are
not caught, because the validation episode should fail loudly.

## 7. Per-turn latency budget and measurement plan

**Budget (design targets from F1, not measurements):**

- turn 0 (import, load, warm-up, first act) ≤ 20 s, leaving ≥ 40 s of the bank;
- steady-state p99 ≤ 500 ms and max < 900 ms;
- the sum of per-turn excess over 1 s stays ≤ 10 s for a full episode.

**Arithmetic estimate (unmeasured).**

- The CPU path runs the padded trunk: 699 entity tokens + 2 player + 1 global +
  4 scratch + 1 plan + 2 critic = **709 tokens**.
- Linear FLOPs are about 2 × 4.22M trunk params × 709 ≈ 6.0 GFLOP.
- Attention is about 8 layers × 4 × 709² × 256 ≈ 4.1 GFLOP.
- That is ≈ 10 GFLOP per row. At an assumed 20–60 GFLOP/s single-thread fp32
  it takes ≈ 170–500 ms.
- The grammar heads run 7 unit slots batched over actors, then ≤ 10 market
  positions: many small kernels whose cost is dispatch-bound, not
  FLOP-bound.

This estimate cannot replace the measurement.

**Measurement (T7, `scripts/benchmark_kaggle_agent.py`):**

- Inputs: the extracted tarball's `main.py`, loaded with the real
  `get_last_callable`, and the recorded Kaggle observations from the local
  episode (T8). Include early, mid and densest-actor turns, and a synthetic
  241-actor state from the 1.3 oracle corpus.
- Report, separately:
  - turn 0 time, and import / load / warm-up time;
  - per-turn encode, forward and decode ms, as p50/p95/p99/max over all 719
    turns per seat;
  - thread counts 1 and 2.
- Receipt: host CPU model, `nproc`, image digest, torch version and source
  commit, in JSON under `ops/rebuild-2026-09-29/7.4/`.
- Host: the pod CPU inside the Kaggle image, with `docker run --cpus=N`
  matching the thread count. Kaggle's vCPU count is unknown, so the receipt
  says "pod CPU, not Kaggle hardware".
- The only Kaggle-hardware evidence would come from the validation episode's
  agent logs (`duration`), which needs an owner-approved submission.

If p99 is over budget, stop (see the stopping conditions). The candidate
remedies are all separate, measured changes:

- single-row unpadded attention, proved bitwise-equal to the masked padded
  path;
- thread count;
- int8 dynamic quantization, which changes actions, so it needs a measured
  agreement rate and the owner's acceptance.

## 8. Replay parity test

`tests/kaggriculture/test_kaggle_agent_parity.py` has fast tests on the tiny
CPU preset for the Mac, plus a pod-marked full test.

1. **Observation bytes.** For every recorded state, the seat binding's `[1,1]`
   row must be byte-identical (`tobytes()` per field, all 29 fields) to:
   - `write_env`'s row for that seat, built from the full two-seat header;
   - the native env's observation row after replaying the same seed and
     actions. This needs `ObservationGame::from_seed(config, info.seed)` plus
     `step`; lifecycle access follows 1.4/1.5's API.

   Seeds come from the local kaggle-environments episode (`env.info["seed"]`),
   so the Python engine, the Rust engine and the view all meet. Rust/Python
   engine parity itself belongs to 1.1b; any divergence here names the first
   field, step and seat.
2. **Actions.** The packaged path is tarball `main.py` → `agent(obs, config)`.
   The training path is `KaggricultureTransformer` from the same checkpoint on
   the native row, fp32 CPU, then native decode. With `deterministic=True`, the
   token arrays, lengths and decoded JSON must be identical at every recorded
   turn.

   A sampled-mode variant calls `torch.manual_seed(k)` before each call on both
   paths and must also match. This proves that the packaged agent consumes no
   RNG outside the model.
3. **Scope.** GPU BF16 training rollouts are not expected to match
   token-for-token. Their agreement rate is a diagnostic reported separately,
   not a gate.
4. **Loader.** `get_last_callable(main.py source, path=…)` returns `agent`. A
   configuration carrying `__raw_path__` is accepted and the key dropped.
   Buffer poisoning does not change the output.

SHA-256 and byte size. Weights and tarballs stay out of git (`.gitignore`);
only the manifest and receipts are committed. The model gets no opponent
identity, seed or seat information beyond its own legal view, and
checkpoint selection uses no opponent identity.
