## Data flow (exact APIs)

New file `scripts/kaggriculture_bc/prepare.py` (next to the selector; the
reference's `ops/` location is not retained). CLI:
`prepare.py SELECTED.zip OUT_DIR --workers N`. Episodes are processed
independently in a process pool, one worker per episode.

**A. Selection admission.** Read `selection.json` from the ZIP and validate it
strictly: exact keys, 252 records, split ∈ {train, validation}, unique
basenames. Before parsing a payload, check its SHA-256 and byte length against
the record. Use explicit `ValueError`s, not `assert`, which `-O` strips.

**B. Episode envelope.** `json.loads` (it preserves key order). Require
`len(steps) == 720`, two seat entries per step, and `info.EpisodeId` equal to the member
basename (a local non-slice episode has both `info.EpisodeId` and `info.seed`).
Record `info.seed` in the manifest as custody only. It is not used for
encoding (placeholder header seed, below) and is not a model input. Agent
names and team names are never read into shards or the manifest. Discover the
shared keys from `specification.observation[*].shared` (on the local sample:
`day, farms, hour, market, step, town`).

**C. Explicit-state header per turn.** For `t in range(719)`: the observation
is `steps[t][seat].observation`, and the label is `steps[t+1][seat].action`.
The owner restated this pairing on 2026-09-29 ("kaggle obs shd be step+1"): the action that answers the observation at step t is recorded at step t+1. A pairing test must prove it rather than assume it: for the four official episode fixtures (`engine_rs/fixtures/episode-*.jsonl.gz`), applying the label `steps[t+1].action` through the vendored engine to the state built from `steps[t]` must reproduce `steps[t+1]`'s public and private state for every t. A deliberately shifted pairing (`steps[t].action`) must fail that test.
Seat 1's shared keys are copied from seat 0 (seat 1 omits `step` in the
sample). Build one `TraceHeader` (`engine_rs/src/lib.rs:818`) per turn:

```python
{"format": "kaggriculture-re-parity-v1", "seed": 0,   # placeholder, as the reference
 "configuration": episode_configuration,              # verbatim, key order kept
 "shop_schedule": [], "rng_schedule": [],
 "initial": {"public": {k: obs0[k] for k in ("step","day","hour","farms","market","town")},
             "privates": [obs0["private"], obs1["private"]]},
 "terminal_banks": [], "transitions": 0}
```

The Rust `Config` is `#[serde(default)]` (`lib.rs:668`). A missing key would
therefore silently take a default. Before serialization, prepare requires the
full key set: `episodeSteps, boardSize, startingMoney, maxMarketOrdersPerTurn,
turnsPerDay, shedCapacity, weedSpawnChance, townShopUnlockInterval,
townShopSellInterval, townCenterSellInterval, farmHandCostMult, marketParams`.
The only extra keys the encoder accepts are `actTimeout`, `runTimeout` and
`seed` (`src/kaggriculture/config.rs:76`). The encoder also rejects non-empty
`marketParams` and `market.params`, and checks the clock
(`observe.rs:241`). Serialize with `json.dumps` and **no `sort_keys`**, so
inventory and shed insertion order survive (`serde_json` has `preserve_order`
on in both crates).

**D. Observation encoding (all 719 turns).** Allocate CPU buffers of `[B,2,…]` for all 29
fields (28 `_SCHEMA` fields, `python/owl/kaggriculture/types.py:109`, plus
`can_act [B,2,252]`). Call `rs.encode_kaggriculture_headers_into(headers_json,
**arrays)` in batches of B = 32 turns. The binding preflights every header
before it writes anything, and a failure names the offending `env`. **An
encoder error on a real recorded state is fail-fast**: stop the episode and
report the episode, turn, field and error. Every turn is a real recorded state, so any
rejection is a 1.3 envelope finding to fix or record, not a row to drop. (The
reference encoded only its 158,772 admitted states; encoding rejected turns too
is a deliberate, stricter difference, needed because step E reads its plan
inputs from these rows.) After each batch, run
`KaggricultureObsBatch.check_contract()` on the torch views, then keep the rows until step E
decides admission, and copy the admitted rows out before the buffers are reused.

**E. Action admission (both seats, strict, counted).**

1. *Envelope normalization.* This replicates the reference exactly and is
   counted, not silent. The raw action must be a JSON object whose keys are a
   subset of `{farmer, hands, market}`; otherwise the seat is rejected as
   `action envelope`. The reference did `raw.get(k) or []` for `hands` and
   `market`, which maps **every falsy value** to `[]`: absent, `null`,
   `false`, numeric zero (`0`, `0.0`), `""` and `{}`. An in-memory probe of
   the pinned reference codec admitted all eight `{hands, market} × {false,
   0, "", {}}` combinations with a PASS farmer and no hands (Codex rereview).
   Preparation reproduces that rule, because acceptance item 2 requires
   per-episode admission equal to the reference, and counts it per episode,
   field and kind as `normalized_{hands,market}_{absent,null,false,zero,
   empty_string,empty_object}`. An empty list is not a normalization. Any
   truthy non-list value is rejected, not coerced (the reference also
   rejected it, through `TypeError` or its codec). A missing `farmer` becomes
   `null`, which the grammar rejects. Short `hands` lists are **not** padded:
   the grammar rejects them as `hand count`, where the reference padded with
   Python `None` and then rejected the turn. Admission is the same; only the
   message differs. No omission-to-PASS repair is made (stream D point 7
   stands). How often each kind occurs in the selected slice is unknown until
   the run (Q1).
2. *Plan inputs from the encoded observation, not from Python JSON.* The
   grammar plan's `actors` is `actor_mask[env, seat, :241].sum()` (own actors
   occupy slots 0–240, `docs/kaggriculture-contract.md:43`). Its `order_limit`
   is `order_limits[env, seat]`, and `hire_limit = 241` (the
   `KaggricultureActionConfig` default). Cross-check `actors == 1 +
   len(obs[seat].farms[seat].hands)` and
   `order_limit == configuration.maxMarketOrdersPerTurn`. A mismatch is a hard
   error.
3. *Encode.* Call `rs.kaggriculture_encode(json.dumps(action), actors,
   order_limit, 241, out)` into a C-contiguous int64 `[252,12]` view. This is
   the 1.4 signature (`briefs/1.4.md:48,314`). The function is transactional:
   on error it leaves `out` untouched and raises `ValueError`. Encode **both**
   seats every turn and record each seat's error. The pair is admitted only if
   both seats encode. The reference-comparable *first rejection* is seat 0's
   error if there is one, otherwise seat 1's. Do not use the 1.5 batch helper
   `encode_actions`: it raises on the first failure and cannot count
   rejections.
4. *Round trip.* For every admitted seat, check that
   `json.loads(rs.kaggriculture_decode(tokens, length, actors, order_limit,
   241))` equals the normalized action. The comparison uses Python equality on
   parsed JSON, and list order matters.

Category mapping. The rows are the reference's first-rejection totals; the new
text is the grammar's message prefix.

| Reference first rejection | Pairs | New grammar prefix (`grammar.rs`) |
|---|---:|---|
| `unknown market command` | 14,007 | `unknown market command` |
| `unsupported unit command arguments` | 5,621 | `unsupported unit command arguments` |
| `target violates syntax mask: market_item` | 1,668 | `market item syntax` |
| `extra hand commands` | 1,102 | `extra hand commands` |
| `market queue exceeds configured limit` | 17 | `market queue limit` |
| `quantity must be an integer in 0..1023` | 1 | `quantity range` |

The vocabularies, slot widths, item masks, the unit-quantity ≥ 1 rule and the
hire rule (`actors + hires < hire_limit`) match the reference codec. The check
*order* differs. The reference built every frame and then applied its masks.
`grammar::encode` checks keys, then hand count, then queue length, then each
unit, then each market order, then `validate_program`. A pair with two defects
can therefore change category, but it cannot change admission.

**F. Shard write.** Write each episode as it completes. Nothing is
concatenated across the corpus (the reference held whole episodes of flat
features in memory).

## Shard format consumed by `train_bc.py` (5.2)

Schema id **`kaggriculture-bc-shard-v1`**. Each episode is one
`np.savez_compressed` file at `OUT/<split>/<day>-<episode_id>.npz`. T is the
number of admitted turns in that episode.

| Array | dtype | shape | Note |
|---|---|---|---|
| `schema` | `<U` 0-d | `()` | `"kaggriculture-bc-shard-v1"`; the loader rejects anything else, including old `features/context` shards |
| 28 observation fields | contract dtype (int64 / float32 / float64 banks / bool) | `[T,2,…]` | names, shapes and dtypes exactly as `_SCHEMA` |
| `can_act` | bool | `[T,2,252]` | loads into `KaggricultureActionMask` |
| `tokens` | int64 | `[T,2,252,12]` | full STOP-terminated program, zero tail |
| `lengths` | int64 | `[T,2]` | frames including STOP |
| `turn` | int64 | `[T]` | original index t; rejected gaps stay visible |

Seat axis index 0/1 is the recorded seat. Each row is that seat's own view,
with player token 0 as self. There is no rival-private data, episode ID,
opponent name or seed in any array. Tokens are stored at the contract's int64
dtype. A loader may compact them in memory only through a lossless,
range-checked cast declared in its own code, and must cast back to int64
before `evaluate_actions`.

Dense size is about 282 KB of observation plus 48 KB of tokens per paired
turn, so roughly **52 GB for 158,772 turns**, mostly zero padding. The GPU pod
has about 25 GB of free pod disk (plan "Resource fit"). Compression is
therefore required, and the first pod step measures the compressed bytes and
the load time on one episode. Residency (host memory versus GPU) and the rank
split belong to 5.2. The reference used `[rank::world]` rows per file.

5.1 makes no value-target decision. The reference `train_bc.py` froze the
critic. 5.2 decides the critic treatment by Isaiah's convention and records
the choice. For that, the manifest carries each episode's `terminal_banks`
(`rewards`), and seat order is structural.

The split is per episode, taken from `selection.json`. All turns of an episode
go to its split directory. Before writing, prepare re-checks that no basename
appears in both splits, and that `info.EpisodeId` equals the basename.

## Custody manifest

`OUT/manifest.json` is strict JSON, and a loader validates its keys:

- run: schema id, `git rev-parse HEAD`, `Cargo.lock` and `uv.lock` SHA-256,
  SHA-256 of the built `owl.rs` extension file, observation schema 3,
  contract document v4, grammar tables version 1, `hire_limit` 241, the
  command line and the worker count;
- source bytes: path, bytes and SHA-256 of every Python file the run executed
  from the checkout (every `sys.modules` entry whose `__file__` lies under the
  repository root, which includes `prepare.py`, the allocator and
  `reference_admission.py`), of `select_replays.py` as run for selection, and
  of the exported reference `actor_codec.py` (which must equal its pinned
  `88ed3d44…40e5d6`);
- source: volume `4llk4uaf20`, source root, the selected ZIP's SHA-256 and
  path, the `selection.json` SHA-256;
- per episode: member, `episode_id`, split, `source_sha256`, bytes,
  `info_seed`, `terminal_banks`, `paired_turns` (719), `admitted`,
  first-rejection counts, per-seat rejection counts, normalization counts,
  shard path, shard SHA-256 and bytes;
- totals by split.

**Source identity.** A HEAD and a dirty flag cannot identify modified
preparation, allocator or oracle code, so a dirty run is refused, not
flagged. On both execution routes (data pod and GPU-pod fallback), selection
and preparation run from an immutable clean checkout of the committed
revision: a fresh clone or a dedicated worktree, never a shared working tree
that a learner or an operator may edit. At start, `prepare.py` requires
`git status --porcelain --untracked-files=all` to be empty and records HEAD
and the source-byte hashes above. Before publishing `manifest.json` it
re-checks: HEAD unchanged, the tree still clean, every recorded file's
SHA-256 unchanged, and the extension hash unchanged. Any mismatch is a hard
error and no manifest is written. `OUT` lies outside the checkout, so the
run's own output cannot dirty it.

**What is tracked.** Shard NPZ bulk and `manifest.json` stay out of git. The
committed receipt in `ops/rebuild-2026-09-29/5.1/` holds a compact
**per-shard custody inventory** (`shard-inventory.json`: for each of the 252
shards its path relative to `OUT`, split, bytes and SHA-256, plus the same
three fields for `manifest.json`), as the
[custody Decision](../../../cookbook/decisions/evaluation-preserves-generality-and-evidence.md)
requires for local bulk artifacts. It also holds the totals, the acceptance
diff and the logs.

## Acceptance against the reference receipt

The reference receipt: 252 episodes × 719 = **181,188 paired turns**;
**158,772 admitted** (139,835 train + 18,937 validation); **22,416 rejected**
(category table above).

1. **Identity.** The 252 members, their order, split and SHA-256 equal
   reference `data-manifest.json` `selection.episodes`.
2. **Admission per episode.** `admitted` equals the reference `turns` for all
   252 episodes, so the totals match exactly. The reference records only
   per-episode counters, so differences are attributed **per turn and seat**
   by a differential oracle. `git show` the stdlib-only reference
   `python/owl/kaggriculture/actor_codec.py` (SHA-256 `88ed3d44…40e5d6`) into
   a temporary directory, load it by path, and rerun the reference admission
   rule on the same payloads. No native code or reference edits are involved.
   The reference loop stopped at the first failing seat, so seat 1 was never
   evaluated when seat 0 failed. The harness instead evaluates **both
   reference seats independently** (normalization plus `encode_action` per
   seat), records each seat's result, and only then derives the historical
   first rejection (seat 0's error if any, otherwise seat 1's) for comparison
   with the receipt. Every (episode, turn, seat) where the two codecs
   disagree is listed with both messages. An explained difference must name
   its rule, for example envelope normalization or a grammar change. This
   refresh ran that oracle on one local episode outside the slice
   (114406062): 719/719 admitted, in 0.2 s
   (`../checks/5.1-brief-refresh/ref-admission-probe.log`). The full-slice
   oracle cost is dominated by JSON parsing.
3. **Category totals.** After the prefix mapping, category totals equal the
   reference's, or each shift is attributed to check order by the per-turn
   differential.
4. **Token equality.** For every turn both codecs admit, the new int64 tokens
   equal the reference int16 frames cast to int64 (`SLOT_NAMES` order), and
   the lengths are equal. The decode round trip (E4) holds for every admitted
   seat.
5. **Observation.** No encoder rejection. `check_contract` passes on every
   batch. The actor-count and order-limit cross-checks pass, and `lengths ≤
   can_act.sum(-1)` holds.
6. **Custody.** Reloading every shard reproduces its manifest hash and
   `_SCHEMA` dtypes and shapes. A shard with an old or missing `schema` is
   rejected. The committed `shard-inventory.json` equals the manifest's shard
   entries and the bytes found on the GPU pod after transfer. The manifest's
   source-byte hashes match the committed revision's files.

Out of scope for acceptance: count agreement is not feature correctness
(1.3's corpus qualification covers that), and nothing here measures BC policy
quality.
