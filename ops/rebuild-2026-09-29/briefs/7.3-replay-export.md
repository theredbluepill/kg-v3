## Kaggle episode JSON

The archived `framework-core.py:515` (`Environment.toJSON`) defines the envelope:

```text
id, name, title, description, version, module_version,
configuration, specification, steps, rewards, statuses, schema_version, info
```

`schema_version` is 1. `specification` carries `action`, `agents`, `configuration`,
`info`, `observation`, and `reward` schemas. `steps` is a list of two-seat state
lists. Each seat state carries `action`, `observation`, `reward`, `status`, and
framework `info`. Top-level `rewards` and `statuses` mirror the last seat states.
Do not falsely label a native-produced replay as executed by the Python framework:
keep the target framework version and native exporter/source identity explicit in
replay `info` or a custody sidecar.

- `steps[0]` is the initial observation; its action has no preceding transition.
  For transition `t`, the submitted seat action is stored in
  `steps[t+1][seat].action`, beside its **post-action** observation. The archived
  framework `step` (257–305) and reference BC preparation agree on this timing.
- Public observation fields are `step`, `day`, `hour`, `farms`, `market`, `town`.
  `farms` is seat-ordered; each farm has money, row-major tiles, farmer coordinates,
  ordered hand coordinates, unlocked quadrants and hires today. Tile payloads are
  `null`, `"LOCKED"`, or structured game tile objects; preserve them verbatim.
- Each seat has its own `player`, `private`, and framework time budget.
  `private` contains `shed`, `seeds`, and actor-ordered `inventories` (farmer first,
  hands after). Never substitute the other seat's private state.
- The archived game schema marks farms/market/town/day/hour shared, and the
  framework adds shared `step`. Serialization may omit these from seat 1;
  reconstruct only fields marked `shared` in the episode's specification from
  seat 0. The archived framework's `__get_state`/`__get_shared_state` and reference
  `prepare.py` implement that distinction.
- Engine actions are objects with `farmer`, `hands`, `market`. Commands are ordered
  arrays such as `["WATER"]`, `["PICKUP", "WHEAT", 2]`, or
  `["SELL", "WHEAT", 0]`. Preserve omitted quantity versus explicit zero,
  empty queue entries, unit positions and all order positions. A successful export
  records what was submitted, including commands that execute ineffectively.
- `info.seed` is the resolved episode seed. Archived
  `framework-utils.py:199` (`resolve_episode_seed`) uses existing `info.seed`, then
  configured seed, then a random fallback; it writes `info.seed` and clears
  `configuration.seed` to null. Recovering a seed from that null field is wrong.
  Seed custody is host metadata and must never enter model inputs.

No raw public Kaggle episode JSON was opened in this investigation. The envelope
above is source-derived and cross-checked against the reference BC reader; native
fixture contents were directly inspected. Framework timeout/error semantics are
not established by native traces of completed legal games.

## Native trace JSONL and replay input

The first JSONL record has the following observed shape:

```text
type: "header"
format: "kaggriculture-re-parity-v1"
source: {episode_id, module_version, engine_sha256, replay_sha256}
seed: exact JSON integer
configuration: resolved public/framework configuration (seed null in fixtures)
shop_schedule: ordered shop names, including repeated names
rng_schedule: [{day, weed_rolls: [numbers...]}...]
initial: {public: {step, day, hour, farms, market, town}, privates: [seat0, seat1]}
terminal_banks: [seat0, seat1]
transitions: number of game transitions
```

Every following record is:

```text
{type: "transition", from_step: t, actions: [seat0, seat1],
 expected: post_transition_public, privates: post_transition_privates,
 statuses: [seat0, seat1], rewards: [seat0, seat1]}
```

The native CLI does **not** read this gzip/JSONL representation directly. Its
`ReplayInput` is one JSON object `{header, transitions: [{actions}, ...]}`.
It emits one `StepSnapshot` per initial/successor state:
`{public, privates, done, statuses, rewards}`. The JSONL oracle's `expected` maps
to snapshot `public`; `done` is checked separately. `type`/`source` are fixture
metadata beyond the typed native header. Native `TraceHeader` still requires
the schedule, initial, terminal-bank and count fields, even though several are
not used to construct a game.

`Game::from_seed_header` validates the format/configuration/player counts, creates
the standard initial state from configuration, and sets the resolved seed. It
does **not** load the supplied initial state, RNG schedule, shop schedule or final
banks as answers. `Game::from_header` loads an explicit state and therefore cannot
prove a seed-header round trip. The schedules can be empty in a newly generated
native header; if recorded as diagnostics, their provenance must be explicit.

All four fixtures contain 29 `rng_schedule` records with 200 rolls each. These
are legacy diagnostic schedules, not a promise that the engine consumes 200 draws:
`end_of_day` only draws for null tiles, in seat/y/x order, then draws a shop when
eligible. It reinitializes Python-compatible RNG each day with
`(seed * 1_000_003) XOR day`. Exact integer seed and exact actions/configuration
are sufficient; external RNG injection would invalidate the test.

## Export contract to implement after the native seam lands

1. At game start, bind a unique evaluation/game ordinal to its actual **resolved
   per-game seed**, resolved configuration, source/engine/schema versions,
   candidate/incumbent checkpoint hashes and seat assignment. Capture the consumed
   seed, not base seed, current `next_seed`, or a guess from environment index.
   Contract v4 consumes seeds at construction and explicit resets, then at
   simultaneous terminal resets in environment-index order.
2. For selected games, retain the exact executed token lengths and tokens, plus
   decoded engine actions in seat order. Decode against the pre-step actor count
   and order limit using the native grammar. STOP terminates the token program;
   it is not an extra game transition. Retain NONE/EMPTY and omitted/explicit
   quantities as native decoding specifies, without a second Python decoder.
3. Preserve list order and insertion order of inventories and shed mappings,
   including zero-valued keys. Do not `sort_keys=True` these payloads. Movement,
   hand indices, ordered market queues, capacity-limited deposits and duplicate
   shop positions make order observable. Use exact JSON integers and round-trip
   float64 money; never regenerate full state from scaled float32 model tensors.
4. Prefer an opt-in evaluation recorder that saves seed/configuration and decoded
   actions, then materializes full snapshots through native seed replay after the
   game. This avoids JSON in ordinary collection. Compare the replay against
   captured initial/terminal snapshots, per-transition banks and any retained
   diagnostic checkpoints; a replay compared only with its own output is circular.
   Exact all-state certification additionally needs captured full snapshots at
   every transition of the selected games (or an independent engine oracle).
   Limit this diagnostic cost to those selected games and measure it separately.
5. Capture terminal evidence **before auto-reset**. The default is 719 transitions,
   720 observations, final step 719, statuses DONE and raw-bank rewards. Contract
   v4's returned terminal-step observation belongs to the new game; terminal
   metrics/banks belong to the completed game. Copy ephemeral evidence before
   the next native call. PPO shaped rewards stay in diagnostics, not Kaggle rewards.
   Artificial truncation is a partial episode, not a fabricated DONE/winner.
6. Serialize Kaggle `steps` with the timing above, `info.seed`, the full supported
   public configuration and pinned schema. Also retain a source-bound seed header
   and action tape for native verification. Native runtime errors or failed
   transactions must produce an explicit incomplete/error record, never a
   successful replay with missing turns. Keep the eight exported selections
   reproducible, including both model-seat assignments where applicable.

The native replay adapter should reject unsupported v4 configuration, missing
seed, non-integral/negative seed, incorrect action count, nonconsecutive steps,
count mismatch and malformed terminal records with explicit errors. Wider-than-
53-bit seeds must survive JSON/Python/Rust without float conversion. A browser
display is not an authoritative parser for those seeds.

## Checks actually performed and remaining gaps

Read-only standard-library decoding/hash checks passed for **4 fixtures / 2,876
transitions**: header count 719, consecutive `from_step`, successor `step=t+1`, two
actions/private states/statuses/rewards per transition, ACTIVE until the final
DONE pair, and final rewards equal header banks and final farm money. SHA checks
also matched the four local archived source files above. This is structural
inspection, **not an engine replay test**. No unit-test suite, build, native
transition, training run, download or network request ran for this brief.

Open implementation seams: v4 still needs a diagnostic way to retain resolved
per-game seeds and completed full-state snapshots; model tensors/terminal banks
alone are insufficient for a full independent state comparison. The exact pinned
framework schema must be available on the implementation host for final envelope
validation. Raw public episode inspection and native exporter round-trip remain
pending. Existing cookbook search (`replay`, `export`, `round-trip`, `seed header`)
found the native/BC records and the PPO record's explicit missing-export limit;
none establishes an already-qualified Kaggriculture writer.
