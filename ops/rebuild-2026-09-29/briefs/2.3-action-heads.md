## 1. Topology (Isaiah's actor blocks; the heads are the only game-specific part)

- **`actor_input_proj: nn.Linear(3D, D)`** over `[entity ‖ self player ‖ plan]`, following Isaiah's `source_actor_input_proj` pattern. For unit frames the entity is `own_actor_hidden[:, a]`; for market frames it is the plan hidden (there is no market entity), as in the reference. **Muon-eligible**, as in Isaiah's model.
- **`actor: KaggricultureGrammarActor(nn.Module)`** holds everything game-specific:
  - `source_norm: LayerNorm` (Isaiah's actor normalizes its input)
  - `market_position: nn.Embedding(11, D)` (queue position)
  - `slot_embeddings: nn.ModuleDict` for within-frame prefix conditioning: `unit_kind 20`, `unit_item 16`, `unit_quantity_present 2`, `unit_quantity_high 32`, `market_kind 8`, `market_item 16`, `market_quantity_high 32`
  - `heads: nn.ModuleDict` of `OutputProjectionMLP(trunk_cfg, width)` for the 9 sampled slots: `unit_kind`, `unit_item`, `unit_quantity_present`, `unit_quantity_high`, `unit_quantity`, `market_kind`, `market_item`, `market_quantity_high`, `market_quantity`
- **Implicit slots:**
  - slot 0 `unit_actor`: the unit-frame actor ordinal; zero in market, STOP, padding and inactive frames
  - slot 2 `unit_target`: reserved, always 0
  - slot 11 `stop`: set on the STOP frame only

  All three have zero density.
- **Conditioning:** `hidden_stage = base + prefix / sqrt(stage + 1)`, where `prefix` sums the embeddings of the slots already chosen in the frame (the reference factorization, rebuilt).
- **Initialization and optimizer wiring (explicit):**
  - `get_input_layers` returns `market_position.weight` and each slot embedding's `.weight` as parameters. `reset_parameters` initializes them as Isaiah's token parameters (normal, std `D^-0.5`). Isaiah's `_init_input_layer` only handles `nn.Linear` / `nn.Parameter`, so the weights are passed, not the `nn.Embedding` modules.
  - `reset_parameters` is extended beyond the current critic-only output reset: every actor `head.out` goes through `_init_linear(..., gain=_ACTOR_HEAD_INIT_GAIN = 0.01)`, giving orthogonal weights and zero bias. Every `head.out` is also returned by `get_output_layers`.
  - `actor_input_proj.weight` and every head's `.up.weight` stay Muon-eligible. The embeddings, `head.out`, norms and biases go to AdamW.

## 2. Grammar tables and masks

`GrammarTables` (typed; built by `python/owl/kaggriculture/gpu_grammar.py`, ported from `gpu_sampling_grammar.py` (C7) and extracted from the native plans (C3, Task 1.2)). `δ0(W)` is a width-`W` mask admitting only 0.

| Slot | Stored table | Effective mask |
|---|---|---|
| 1 `unit_kind` | `unit_kind [20]` | `where(unit_live[..., None], unit_kind, δ0(20))` |
| 3 `unit_item` | `unit_item [20,16]` | `unit_item[kind]` |
| 4 `unit_quantity_present` | `unit_quantity_present [20,2]` | `unit_quantity_present[kind]` |
| 5 `unit_quantity_high` | `unit_quantity_high [2,32]` | `unit_quantity_high[present]` |
| 6 `unit_quantity` | `unit_quantity_low [2,2,32]` | `unit_quantity_low[present, (high == 0).long()]` |
| 7 `market_kind` | `market_kind [8]` | `where(available[..., None], market_kind, δ0(8))`, then HIRE removed where capacity is exhausted |
| 8 `market_item` | `market_item [8,16]` | `market_item[kind]` |
| 9 `market_quantity_high` | `market_quantity [8,32]` | `market_quantity[kind]` |

Expected supports (from `myolie_sampler.rs:147–258` `State::allows`/`advance` and reference `kaggriculture.py:578–675`; the implementer re-derives them, and a test compares every table with the native plans):

- **Unit kind:** `1..18`.
- **Unit item:** `1..12` for kinds 6/7, `1..5` for kind 8, otherwise `{0}`.
- **Unit quantity:**
  - Only kinds 6/7 allow `present = 1`.
  - Absent quantity forces both digits to 0.
  - Present quantity excludes low digit 0 only when the high digit is 0.
- **Market item:** `1..5`, `{1, 9}`, `10..12` and `1..9` for kinds 3, 4, 5, 6; otherwise `{0}`.
- **Market quantity digits:** `0..31` for kinds 3–6, otherwise `{0}`. The extractor asserts that the high- and low-digit supports are equal. Rust moves kinds 4–6 into their quantity-bearing state after slot 8.

## 3. Runtime grammar context and frame placement

The actor receives `actor_counts [B]` (own actors per row), `order_limits [B]`, `hire_limit` (config; default **241**) and `live [B]` (`still_playing`).

```text
unit_live[b,f]     = live[b] & (f < actor_counts[b])
available[b,p]     = live[b] & (p < order_limits[b])        p = 0..10
market_frame[b,p]  = actor_counts[b] + p
market_live[b,p]   = live[b] & (p <= first_final_NONE[b])
lengths[b]         = where(live[b], actor_counts[b] + s[b] + 1, 0)   s = STOP position
```

- Unavailable positions force `NONE`, including the sentinel at `p == order_limits`.
- Padded unit frames use singleton-zero support.
- Inactive rows produce all-zero tokens, length 0, and zero log-probs and entropies.
- **HIRE capacity** counts *submitted* HIREs whether or not they would execute: HIRE is allowed at position `p` iff `actor_counts + exclusive_prefix_HIREs(p) < hire_limit`.

## 4. Sampling (coupled Gumbel, exact categorical)

- **Categorical draws:** exact Gumbel-max (no multinomial). Log-probs and entropies come from masked `log_softmax` over the effective mask.
- **Market kind:**
  - Draw **eight independent Gumbels per market position**, independent across positions.
  - `raw_kind = argmax(scores)` over the initial mask.
  - The **exclusive raw-HIRE prefix count** gives `can_hire`. Where capacity is exhausted, HIRE is masked and the argmax is re-taken over the **same perturbed scores** (no redraw); the corrected outcome can be `NONE` or `EMPTY`.
  - Density evaluation uses the **exclusive final-HIRE prefix count** of the final kinds.
- **STOP:**
  - STOP is the first final `NONE`, which **keeps its kind probability** in slot 7.
  - The forced sentinel at `p == order_limits` has zero density.
  - Later positions are marginalized: zero log-prob and entropy.
  - `EMPTY` consumes an order.

## 5. Replay validation (`evaluate_actions`), after the reference `_decode` (`kaggriculture.py:747–783`)

`evaluate_actions` must reject malformed programs itself, because PPO and BC replay never call native `step`. Native admission on `step` (Task 1.4) still exists as a separate guard.

1. **Before any policy kernel:** check that `tokens` and `lengths` shapes are `[E,2,252,12]` / `[E,2]` and that both are `int64` (a Python-side check, no device sync).
2. **Safe indexing:**
   - Every replay-derived gather, table lookup and embedding index uses a clamped temporary index. The original value's validity goes into device flags.
   - Repaired values are never admitted or returned. A host check after the kernels cannot undo an out-of-range access, so indices must be safe before execution.
3. **Three device flag groups**, all computed in the tensor core:
   - **support:** every chosen value is inside its prefix-dependent effective mask (§2 and §3).
   - **length:** `lengths` equals the reconstructed `where(live, actor_counts + s + 1, 0)`.
   - **canonical equality:** the reconstructed canonical token tensor equals the supplied tensor **element for element**. This covers:
     - actor ordinals
     - the reserved target
     - unit fields in market frames and market fields in unit frames
     - STOP bits
     - every padding element
     - all-zero tokens for inactive rows
4. **One synchronization:**
   - Aggregate the flags into one compact vector, then make one host transfer and branch.
   - This runs outside the compiled tensor core and before the result returns to loss computation, as the reference `_check_flags:121–126` did.
   - The error message names the failing group.
   - `valid` stays on an explicitly typed internal policy result. `ModelOutput` gets no validity field.
5. **Sampling path:** `forward` makes **no** host sync; validity there is guaranteed by construction and checked in tests. Removing that sync is a throughput choice, not the L6 corruption remedy. L6 is handled by the dispatch guard (2.1), Task 3.6's first-minibatch log-ratio alarm and Phase 6 qualification.

## 6. Outputs

- `KaggricultureActions(tokens [E,2,252,12], lengths [E,2])`.
- **Log-probs:**
  - `ModelActionLogProbs.event [E,2,252,12]`: per-frame, per-slot densities, zero for slots 0, 2 and 11.
  - `per_player_entity = event.sum(-1)`
  - `launch = zeros_like(per_player_entity)`
- **Entropies** mirror the log-prob layout:
  - `entropies.event` has the same shape.
  - Its sum over slots gives `per_player_entity`.
  - `components[name] = event[..., slot]`.
- `ModelOutput` includes the critic values (2.2).
- `evaluate_actions` replays the tokens teacher-forced through the same code path as sampling.

## 7. Tests (tiny CPU; synthetic tables until 1.2)

1. **Replay invariant (L6 regression shape):**
   - Freeze the weights, sample once, and save tokens, lengths and per-slot log-probs and entropies, with their frame sums.
   - Re-evaluate the saved actions:
     - (a) as the same batch
     - (b) split into minibatches of different sizes
     - (c) permuted, re-batched, then restored to the original order
   - Every result must match the **saved** values to ≤ 1e-5 (FP32 eager). A second `forward` is never the reference.
   - Cases: dense (241 actors, 10 orders), HIRE capacity, STOP at every position, and mixed actor counts, order limits and inactive rows within one batch.
2. **Masks against the native plans:**
   - Every table row matches the native plans.
   - Quantity cases:
     - omitted unit quantity
     - rejected explicit unit zero
     - values `1`, `31`, `32`, `1023`
     - accepted market zero
3. **Gumbel exactness:** empirical frequencies of 20k draws match the masked softmax for one slot (chi-square bound).
4. **HIRE coupling by enumeration** (3 positions, 8 kinds, budgets 0/1/2/3/10):
   - The test drives the **actual** sampler and replay implementation.
   - The enumerated joint probability of every final program equals the replayed density, and the total sums to 1 within 1e-9.
   - Correction outcomes include both `NONE` and `EMPTY`.
5. **STOP and marginalization:**
   - Post-STOP positions contribute 0 log-prob and entropy.
   - The first final `NONE` keeps its slot-7 density; the forced sentinel has zero density.
   - `lengths` counts every frame including STOP.
6. **Malformed-program rejection:** one test per flag group, each raising with the group named:
   - out-of-support value
   - wrong length
   - non-canonical actor ordinal, reserved target, cross-kind field, STOP bit or padding
   - nonzero inactive row
   - out-of-range index (no device fault)
   - wrong dtype or shape
7. **Compiled density and gradient:** the reference CPU `backend="eager", fullgraph=True` density/gradient test (`tests/kaggriculture/test_model.py:483–505`), with host validation outside the captured core. Plus a finite-difference check of the `evaluate_actions` log-prob with respect to one head weight.
8. **Seat isolation and statelessness** through the heads.
9. **Topology and initialization:**
   - `actor_input_proj` is `Linear(3D, D)` and Muon-eligible.
   - The heads are `OutputProjectionMLP`, with `.up` in Muon and `.out` in AdamW.
   - The embeddings live only under `actor.` and are listed by `get_input_layers` with std ≈ `D^-0.5` after reset.
   - Every `head.out` has singular values = 0.01 and zero bias after `reset_parameters`.
10. **Budget:** the full preset has between 6,000,000 and 10,000,000 parameters (owner decision).
11. **Integration (after 1.2):** masks from the native grammar tables decode the recorded reference programs identically (oracle), and the replay invariant holds with the real tables.

## 9. Overflow guards (added from the GEMM-limit audit, `gemm-overflow-limits-audit-and-probe` workflow)

Rationale (corrected after the GEMM-limit probe and Codex `verify-gemm-limits-r1`; the requirements below are unchanged). At our shapes, the torch 2.9 max-autotune mm/addmm Triton template overflows on the **input side**: the A-load offset `K·idx_m` wraps once `M × K > 2^31` while the template's size argument stays int32. Output-wide GEMMs stayed correct up to `M × N = 2^32`, so the audit's claim that output-store offsets are int32 is withdrawn (`results.md`, "GEMM limits at our shapes"). The width that bounds a compiled region is still `max(in_features, out_features)` over its Linear layers. Backward consumes forward outputs as GEMM inputs: dX = dY·W reads dY at the forward output width. So a training GEMM can wrap at `M × out_features` even when the forward is safe. Fused epilogues that write into a wider buffer were not measured. Keep counting their row stride in the width. The comment at `kaggriculture.py:53` falls under item 1's docstring correction: it should distinguish the observed overflow above the bound from the conservative rejection at equality. The following are in scope for this task because they share `kaggriculture.py`:

1. **Trunk guard semantics (2.1 fix):**
   - Rename or redefine `gemm_kmax` as the maximum over `max(in_features, out_features)` of every `nn.Linear` inside the compiled region.
   - Add a test that enumerates `model.blocks` Linear layers and asserts equality, so a future `mlp_ratio`, SwiGLU or fused-QKV change cannot silently exceed the guard.
   - Correct the docstrings ("inner dim" → "max GEMM operand/output width").
2. **The packed path chunks instead of raising (2.1 fix):**
   - `_run_trunk` splits rows at row boundaries so that every chunk's packed tokens × width < 2^31.
   - Each chunk is packed, run through the trunk and unpacked, then the chunks are concatenated in order.
   - Raise only if a single row cannot fit.
   - Tests: CPU-mocked packed dispatch showing distinct per-chunk inputs, order, the strict bound, and equality with the unchunked result. This removes the predicted fail-fast at teacher-precompute chunks of 16,384 rows.
3. **Head-extent guard (new):**
   - The heads run **eager** in production. The production compiled region stays the trunk only (Task 3.1 must keep it that way and test it).
   - The actor nevertheless chunks rows so that `rows × MAX_FRAMES × max(3D, D, widest head) < 2^31` (about 11,095 rows at D = 256), whether compiled or not. This way a future compile of the head core cannot silently corrupt teacher targets.
   - Tests: a boundary test at the chunk limit ± 1, and equality of chunked vs unchunked log-probs, entropies and flags.
   - The `backend="eager", fullgraph=True` test in §7.7 is a CPU graph-compatibility check only; it is not a production compile mode.
4. **Workload arithmetic** is recorded in the model docs: rollout 256 rows (23× headroom), minibatch 1,024 rows (5.8×), teacher chunk (now chunked).
   - A startup workload assertion over config shapes belongs to Task 3.4 (configs) and is out of scope here; this task adds a note to the plan's Task 3.4.
