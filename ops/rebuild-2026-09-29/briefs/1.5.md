## Shared ABI agreement — identical in 1.4 and 1.5

- Rust `PyKaggricultureEnv`, `#[pyclass(name = "KaggricultureEnv", module = "owl.rs")]`; Python `owl.rs.KaggricultureEnv`.
- Native constructor: `KaggricultureEnv(n_envs, seed, seed_stride, config, reward_config, native_threads, *, hire_limit)`. `config` is validated game-envelope JSON text; `reward_config` is the exact-key dict below. Native has no `pin_memory`: Python pins its own torch allocation. `hire_limit` is required and comes from `action_spec.hire_limit`, never cash.
- Adapter constructor: `KaggricultureVectorizedEnv(*, n_envs, seed, seed_stride, config, reward_config, native_threads, pin_memory, transfer_device, obs_spec, action_spec)`. All arguments required. Here config/reward_config are `KaggricultureGameConfig`/`KaggricultureRewardConfig`; `transfer_device: torch.device` is the device the trainer copies env buffers to; specs are the existing types. It creates native games, allocates **one** caller-owned buffer set (Isaiah's pattern, W:python/owl/rl.py:329–377), and calls non-consuming `observe` into it; no implicit extra reset. (Claude review R1.)
- `observe`, `reset`, `step`, `truncate_envs` take the same 29 observation buffers and six transition buffers, in the inventory's order, all keyword-only. `step(tokens, lengths, *, buffers...) -> dict[str,list[float]]`; others return None. `truncate_envs(mask, *, buffers...)` always means `clear_transition=False`, with no public toggle.
- `observe` publishes cached current observations/transitions without seeds/steps; its consumer is adapter construction. `reset` resets all games and publishes zero rewards/dones, current banks in both bank outputs and zero counters in both econ outputs. `truncate_envs` resets selected games, overwrites **only the selected envs'** observation rows in place and leaves all six transition outputs untouched (Isaiah's in-place semantics, W:src/rl/vec_env.rs:540–547). `observe`, `reset` and `step` write every row, including padding. Every call still publishes all-or-nothing. Truncate publishes through its own infallible selected-row commit (1.4 "Transaction order" step 8b), never through 1.3's whole-batch `ObsStaging::publish` (rereview item 1).
- Transition outputs: `rewards float32[E,2]`, `dones bool[E,2]`, `transition_banks_before/after float64[E,2]`, `transition_econ_before/after int64[E,2,32]`. The counter pair supports independent reward tests/telemetry without reading reset counters. No `econ_counters` alias.
- Adapter: `reset() -> KaggricultureObsBatch`; `step(actions: KaggricultureActions) -> tuple[KaggricultureObsBatch, Tensor, Tensor, dict[str,list[float]]]`; `truncate_envs(mask: Tensor) -> KaggricultureObsBatch`; `terminal_metrics(i: int) -> KaggricultureTerminalMetrics | None`; `state_snapshot(i: int) -> dict[str, JsonValue]`; `seed_state() -> tuple[int, tuple[int,...]]` = (next seed, current env seeds). Native snapshot returns JSON text; adapter parses it. Diagnostics are cold paths.
- Adapter properties: `observations`, the six named transition tensors, `n_envs`, `obs_spec`, `action_spec`, `reward_mode` (win_loss), `pin_memory_enabled`. Properties return the single retained buffer set; their identity never changes.
- **L6 reuse fence (Claude review R1).** One buffer set, no generations. At the entry of `reset`, `step` and `truncate_envs`, before the native call, the adapter calls `torch.cuda.current_stream(transfer_device).synchronize()` when `transfer_device.type == "cuda"` and the buffers are pinned. That is exactly the condition under which ppo.py issues nonblocking copies (W:python/owl/train/ppo.py:561–563). Every read of env buffers in ppo.py and run_ppo.py is enqueued on the current stream before the next env call, and the code base has no side streams (`grep` for `cuda.Stream`/`Event(`/`wait_stream` finds none). So this is an explicit fence, not reliance on the blocking action transfer (ppo.py:2273–2281, 2301). CPU or unpinned runs make no CUDA call. A future reader on another stream must join the current stream before the env call. No trainer API is added.
- Seeds/counter/stride are Rust i64: `0 <= seed <= 2**63-1`, `1 <= seed_stride <= 2**63-1`; every consumption checks the next counter with `checked_add`. Overflow fails before publication. Factory passes `seed=base_seed+rank`, `seed_stride=world_size`; native never adds rank.
- Required reward dict keys: `reward_mode`, `econ_shaping`, `econ_starvation_weight`, `econ_drought_weight`, `econ_cap`, `econ_ineffective_weight`, `econ_ineffective_cap`. No defaults/extras. Mode win_loss; six finite nonnegative f64 coefficients; active caps sum <1. Rust computes rollout rewards; `rewards.py` owns typed config and an independent pure-Python test oracle.
- **Reward admission predicate (one exact rule, rereview item 3).** After the checks above, in IEEE-754 binary64 with each product a single round-to-nearest multiplication (Python `float`, Rust `f64`; no rearrangement or fused multiply-add): if `econ_shaping > 0`, require `econ_cap > 0` and `(econ_shaping * econ_starvation_weight > 0 or econ_shaping * econ_drought_weight > 0)`; if `econ_ineffective_weight > 0`, require `econ_ineffective_cap > 0`. Inactive components impose nothing. Rust `RewardConfig::validate` and Python `KaggricultureRewardConfig` evaluate exactly this expression. Paired cases (W, starvation, drought, cap, ineffective weight, ineffective cap → verdict): (.2, 4, 1, .25, 0, 0 → accept); (.2, 0, 1, .25, 0, 0 → accept); (.2, 0, 0, .25, 0, 0 → reject); (.2, 4, 1, 0, 0, 0 → reject); (1e-300, 1e-300, 1e-300, .25, 0, 0 → reject: both products underflow to 0.0); (1e-300, 1e-300, 1, .25, 0, 0 → accept); (0, 0, 0, 0, 0, 0 → accept); (0, 4, 1, .25, 0, 0 → accept); (0, 0, 0, 0, .001, 0 → reject); (0, 0, 0, 0, .001, .1 → accept). This per-component rule is an **intentional strengthening beyond the pinned reference**, not a port: R's Python rejects only when every active event coefficient is zero (the combined `W*s == 0 and W*d == 0 and ineffective_weight == 0`) and always requires positive caps (R:python/owl/kaggriculture/rewards.py:24,26,41–50); R's Rust requires positive caps and has no event-weight check (R:engine_rs/src/training.rs:42–70).
- `kaggriculture_encode(action_json: str, actors: int, order_limit: int, hire_limit: int, out: numpy.ndarray[int64]) -> int`: transactional write of C-contiguous caller-owned `[252,12]`, returns length. `kaggriculture_decode(tokens: numpy.ndarray[int64], length: int, actors: int, order_limit: int, hire_limit: int) -> str`: canonical JSON. JSON is a cold codec/BC/replay boundary, never live PyO3 step transport.
- `kaggriculture_grammar_tables() -> dict[str,numpy.ndarray[bool]]` and `kaggriculture_grammar_constants() -> tuple[int,tuple[str,...],tuple[int,...]]` land in 1.4. Python codec and `native_grammar_tables(device)` land in 1.5. Constants are version1 and exact names/widths from G:src/kaggriculture/grammar.rs:11,24,38.

## Buffer inventory and lifetime

Every output: 1.5 allocates one CPU torch buffer set, pinned when requested, with one persistent `.numpy()` view each. Exact native-endian dtype, aligned, writable, **C-contiguous**, disjoint regions. Reject Fortran-only contiguous, strided, read-only, overlapping and wrong-shape/dtype buffers before writing. `can_act` is native's parameter for `obs.action_mask.can_act`; do not fork the existing schema.

Readers: O=model/device mapper/rollout observation storage; T=transition storage/GAE; D=diagnostics/reward oracle/evaluation. ### Changes made in this review

- **R1 — L6: one buffer set plus an entry fence, not two generations.** Codex's draft (commit `6ea11d2`) chose two pinned generations with CUDA events that the trainer records at every copy site. It also had truncate publish a whole new generation, which changes Isaiah's `truncate_envs` plumbing (ppo.py:991). That design is correct, but in the canonical loop it buys no overlap: step t+1 needs actions from the forward on obs t, and that forward consumes obs t's H2D copy. It would cost a second pinned buffer set, a full-row copy per truncate, a new trainer API (`record_copy_completion`) and 3.1 edits at every copy site. The contract explicitly allows the synchronous baseline. R1 keeps Isaiah's single caller-owned buffer set and makes the baseline explicit: the adapter calls `torch.cuda.current_stream(transfer_device).synchronize()` at the entry of `reset`/`step`/`truncate_envs` when the device is CUDA and the buffers are pinned. Today that costs ~nothing because the blocking action transfer has already drained the stream, but the contract no longer depends on that incidental sync. Truncate goes back to in place, leaving the transition outputs untouched. 3.1 has no L6 obligation; its only truncation change is 3.2's economic-reward fix (L2). The Mac spy test proves ordering. The L6 evidence is a new pod-only DMA test (1.5 Task C) that fails with the fence removed. Reopen double buffering only if a Phase 6 profile shows overlap would pay. Edited: the shared ABI (both briefs, still byte-identical), the buffer-lifetime text and table, 1.4 "Trainer consumption and L6 contract", the truncate paragraph and Q1, 1.5 architecture, adapter section, Task B/C, factory signature (`transfer_device`), the 3.1 boundary rows, the smoke's discriminating observations and Q4.
- **R2 — reward validation fails fast on inert shaping.** The draft dropped the reference's checks. Without them, `econ_shaping > 0` with `econ_cap = 0`, or with both event weights 0, silently shrinks `terminal_scale` while the penalty can never be nonzero. The checks are ported (C8 is P) into both the native `RewardConfig` and Python `KaggricultureRewardConfig`, and the contract-name mapping (`W`, `death_cap`, …) is stated.
- **R4 — smoke model on the ladder rule.** The pod smoke's tiny model uses `n_heads 1` (head_dim 32, I4), not 4 (head_dim 8).
- **R5 — Isaiah suite command.** Task E runs the plan's Global-Constraints suite (`tests/owl tests/scripts tests/tools -m "not slow"`, without the nonexistent `reference` extra) plus `cargo test --locked`, not only `test_run_ppo.py`.
