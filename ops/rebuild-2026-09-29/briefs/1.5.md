## Shared ABI agreement — identical in 1.4 and 1.5

- Rust `PyKaggricultureEnv`, `#[pyclass(name = "KaggricultureEnv", module = "owl.rs")]`; Python `owl.rs.KaggricultureEnv`.
- Native constructor: `KaggricultureEnv(n_envs, seed, seed_stride, config, reward_config, native_threads, *, hire_limit)`. `config` is validated game-envelope JSON text; `reward_config` is the exact-key dict below. Native has no `pin_memory`: Python pins its own torch allocation. `hire_limit` is required and comes from `action_spec.hire_limit`, never cash.
- Adapter constructor: `KaggricultureVectorizedEnv(*, n_envs, seed, seed_stride, config, reward_config, native_threads, pin_memory, obs_spec, action_spec)`. All arguments required. Here config/reward_config are `KaggricultureGameConfig`/`KaggricultureRewardConfig`; specs are the existing types. It creates native games, allocates A/B, and calls non-consuming `observe` into A; no implicit extra reset.
- `observe`, `reset`, `step`, `truncate_envs` take the same 29 observation buffers and six transition buffers, in the inventory's order, all keyword-only. `step(tokens, lengths, *, buffers...) -> dict[str,list[float]]`; others return None. `truncate_envs(mask, *, buffers...)` always means `clear_transition=False`, with no public toggle.
- `observe` publishes cached current observations/transitions without seeds/steps; its consumer is adapter construction. `reset` resets all games and publishes zero rewards/dones, current banks in both bank outputs and zero counters in both econ outputs. `truncate_envs` resets selected games and preserves **all six** transition outputs byte-for-byte. All publish a complete generation, including unchanged observation rows.
- Transition outputs: `rewards float32[E,2]`, `dones bool[E,2]`, `transition_banks_before/after float64[E,2]`, `transition_econ_before/after int64[E,2,32]`. The counter pair supports independent reward tests/telemetry without reading reset counters. No `econ_counters` alias.
- Adapter: `reset() -> KaggricultureObsBatch`; `step(actions: KaggricultureActions) -> tuple[KaggricultureObsBatch, Tensor, Tensor, dict[str,list[float]]]`; `truncate_envs(mask: Tensor) -> KaggricultureObsBatch`; `terminal_metrics(i: int) -> KaggricultureTerminalMetrics | None`; `state_snapshot(i: int) -> dict[str, JsonValue]`; `seed_state() -> tuple[int, tuple[int,...]]` = (next seed, current env seeds). Native snapshot returns JSON text; adapter parses it. Diagnostics are cold paths.
- Adapter properties: `observations`, the six named transition tensors, `n_envs`, `obs_spec`, `action_spec`, `reward_mode` (win_loss), `pin_memory_enabled`. Convenience properties point at the current generation.
- Adapter `record_copy_completion(obs: KaggricultureObsBatch, *, device: torch.device) -> None` records an adapter-owned CUDA Event on the current stream after every queued read of that generation. Before reuse, adapter calls `event.synchronize()`. CPU uses no event. Two generations only; trainer owns the call placement, not the event.
- Seeds/counter/stride are Rust i64: `0 <= seed <= 2**63-1`, `1 <= seed_stride <= 2**63-1`; every consumption checks the next counter with `checked_add`. Overflow fails before publication. Factory passes `seed=base_seed+rank`, `seed_stride=world_size`; native never adds rank.
- Required reward dict keys: `reward_mode`, `econ_shaping`, `econ_starvation_weight`, `econ_drought_weight`, `econ_cap`, `econ_ineffective_weight`, `econ_ineffective_cap`. No defaults/extras. Mode win_loss; six finite nonnegative f64 coefficients; active caps sum <1. Rust computes rollout rewards; `rewards.py` owns typed config and an independent pure-Python test oracle.
- `kaggriculture_encode(action_json: str, actors: int, order_limit: int, hire_limit: int, out: numpy.ndarray[int64]) -> int`: transactional write of C-contiguous caller-owned `[252,12]`, returns length. `kaggriculture_decode(tokens: numpy.ndarray[int64], length: int, actors: int, order_limit: int, hire_limit: int) -> str`: canonical JSON. JSON is a cold codec/BC/replay boundary, never live PyO3 step transport.
- `kaggriculture_grammar_tables() -> dict[str,numpy.ndarray[bool]]` and `kaggriculture_grammar_constants() -> tuple[int,tuple[str,...],tuple[int,...]]` land in 1.4. Python codec and `native_grammar_tables(device)` land in 1.5. Constants are version1 and exact names/widths from G:src/kaggriculture/grammar.rs:11,24,38.

## Buffer inventory and lifetime

Every output: 1.5 allocates two CPU torch generations, pinned when requested, with one persistent `.numpy()` view each. Exact native-endian dtype, aligned, writable, **C-contiguous**, disjoint regions. Reject Fortran-only contiguous, strided, read-only, overlapping and wrong-shape/dtype buffers before writing. `can_act` is native's parameter for `obs.action_mask.can_act`; do not fork the existing schema.

Readers: O=model/device mapper/rollout observation storage; T=transition storage/GAE; D=diagnostics/reward oracle/evaluation. Each output generation stays bitwise unchanged through the next operation into its alternate, and until its recorded CUDA reads finish before reuse. CPU users copy retained data before reuse. This exceeds the contract's minimum “until next step/reset”, but is not indefinite history. Inputs are borrowed until the native call returns.

## Adapter behavior and generations

`allocate_observation_buffers` writes the29 shapes/dtypes in the copied inventory and constructs **existing** `KaggricultureObsBatch` and `KaggricultureActionMask`. Build exact named NumPy views once in an internal typed `NativeArrays` holder; it mirrors binding parameters, not another policy schema. All tensor storage retained. No `.numpy()`/shape inference/reward recalculation per step; no returned NumPy allocations. Allocate six transition tensors for each generation and pass all 35 keywords explicitly to1.4. Fail requested pinning if allocator unavailable; CPU tests pass pin_memory=False. Orbit behavior is unchanged.

`_Generation` owns obs, six outputs, native views, optional event, and monotonic generation identity. Constructor initializes A via native.observe. Before each mutation choose alternate, wait its outstanding event on CPU, then invoke native. On failure retain active A/B reference and all published bytes; on success switch properties and return that generation. `reset`/`truncate_envs` follow the same protocol, including copying unselected observations/unchanged transitions natively. `terminal_metrics` delegates lazily; snapshot JSON/seed tuple are diagnostics only. Do not expose a lifecycle explicit-state loader.

Action input accepts only KaggricultureActions with exact int64 CPU tensors, `[E,2,252,12]`/`[E,2]`, C-contiguous; rejects GPU/dtype/shape/strides instead of silently casting/copying. Task 3.1 owns device→CPU action transfer and contiguous materialization. Native checks every grammar constraint. Truncate mask must be exact bool CPU `[E]`; no `.cpu()` surprise synchronization in adapter.

Two-generation contract: keep A unchanged when stepping B; before reuse of A wait A's last event. `record_copy_completion(obs,device=...)` identifies the leased generation; CUDA creates/records `torch.cuda.Event` on `torch.cuda.current_stream(device)` **after all reads**, including rewards/dones/masks/transition copies. Unknown batch errors explicitly. Reused A/B objects cannot identify an old lease from object identity alone; callers must obey the generation lifetime. All streams must join before recording. A device wait alone is insufficient to stop native CPU writes, so adapter synchronizes the event. CPU uses no event/cuda calls. Repeated loop steps may proceed without record calls for synchronous CPU consumers, whose retained values must be copied before reuse.

Native methods cannot know whether external CUDA work was queued; the trainer's required completion call is part of the API contract and tested at every copy site in3.1. No claim that A/B alone ensures DMA safety. No claim of fixing historical Task 0.2 GEMM overflow.
