### Validated plan, cursor and decoder

```rust
// Private fields; callers cannot construct invalid state/shape values.
pub struct Shape { actors: u16, orders: u8, hire_limit: u16 }
pub struct GrammarPlan { shape: Shape }
pub struct State {
    shape: Shape, // Binds the cursor to its validated originating shape.
    units: u16, orders: u8, hires: u8, slot: Slot,
    unit: UnitPhase, market: MarketPhase,
    quantity_present: bool, quantity_high_zero: bool,
}
// Private support-equivalence enums, not public action token enums:
enum UnitPhase { None, Ordinary, Transfer, Plant }
enum MarketPhase { None, Hire, Other, Seed, Product, Animal, Sell }

pub fn plan(actors: i64, order_limit: i64, hire_limit: i64)
    -> Result<GrammarPlan, String>;
// Shape, State, UnitPhase and MarketPhase derive Clone/Copy/Debug/Eq/PartialEq/Hash.
// GrammarPlan derives Clone/Copy/Debug/Eq/PartialEq.
impl GrammarPlan {
    pub fn shape(&self) -> Shape;
    pub fn start(&self) -> State;
}
impl Shape {
    pub fn actors(self) -> usize;
    pub fn order_limit(self) -> usize;
    pub fn hire_limit(self) -> usize;
}
impl State {
    pub fn slot(self) -> Slot;
    pub fn allows(self, token: i64, plan: &GrammarPlan) -> bool;
    pub fn advance(self, token: i64, plan: &GrammarPlan)
        -> Result<Option<State>, String>;
    pub fn write_mask(self, plan: &GrammarPlan, out: &mut [bool])
        -> Result<(), String>;
}
pub fn write_can_act(plan: &GrammarPlan, out: &mut [bool]) -> Result<(), String>;
pub fn decode(plan: &GrammarPlan, tokens: &[i64], length: i64)
    -> Result<serde_json::Value, String>;
pub fn encode(plan: &GrammarPlan, action: &serde_json::Value, out: &mut [i64])
    -> Result<i64, String>; // Claude review R1, below
pub fn grammar_tables() -> Result<GrammarTables, String>;
```

`plan` validates `1 <= actors <= 241`, `1 <= order_limit <= 10`, `1 <= hire_limit <= 241` **before narrowing**. `hire_limit < actors` is valid and disables HIRE; it is not a shape error (`R:engine_rs/src/myolie_sampler.rs:73–99`; `R:tests/kaggriculture/test_model.py:440–479`). `State` is observation-local, resets at `start`, and cannot represent post-STOP state except as `None`. It retains its originating `Shape`: `allows` returns false on a different plan shape, and `advance`/`write_mask` return `Err("grammar plan/state shape mismatch")` before changing state/output. Equal-shape plans are interchangeable. `advance` checks `allows` before changing state; an invalid transition returns an error. `allows` returns false for any negative/out-of-width token before token-derived indexing. Mask output lengths must equal the current slot width or 252, respectively; check before touching output. `write_can_act` overwrites all 252 entries with `frame < actors + order_limit + 1`, independently of the selected early STOP (`W:docs/kaggriculture-contract.md:164–168`).

For Task 1.4, one `(env, seat)` supplies a borrowed contiguous **3024-element i64 slice**, representing `[252,12]`, and the original i64 length. No i16 intermediate. Admission order is:

1. Check exact slice size; check signed length in `[actors+1, actors+order_limit+1]`, hence at most 252. Do not cast length or calculate a slice end first.
2. Scan every supplied element against its named slot's `0 <= value < width`, including the padding; reject `-1`, `65537`, `i64::MIN/MAX`, etc. No narrowing or clamping. Iteration ordinals, not unchecked token values, select widths.
3. Require every frame at or beyond `length` to be all zero. These frames are then **ignored by transitions and decoding**. They are not additional NONE/STOP frames. See open question 2 about the reference's weaker padding admission.
4. Walk exactly `length * 12` tokens through the state machine. Reject a terminal before the end, a missing final STOP, or any support/canonical-field violation. Only then render JSON. Input buffers are never mutated or retained.

Task 1.4 derives the plan from the current legal own actor count/configured order limit plus explicit `hire_limit`, not from the program's claimed actor ids. It checks full NumPy shapes/dtypes/layout before selecting each seat slice and adds env/seat to errors. Decode all required seats before committing any game step; batch rollback and publication fences remain 1.4, not claims established by this pure decoder (`W:docs/kaggriculture-contract.md:233–236`; `R:engine_rs/src/training.rs:309–376`).

**Canonical encoder (Claude review R1).** The plan makes the Rust grammar the single source of truth for C6 (`plan.md:63`, Task 1.5 "`codec.py` rebuilt over the Rust grammar"), and Task 5.1 must store v4 tokens for recorded replay actions (`briefs/5.1-bc-data.md:158–165`). Without a native encoder, 1.5/5.1 would have to re-implement enums, arities and HIRE capacity in Python, which is exactly the duplication C6 removes. Add the inverse of `decode`:

```rust
/// Write the canonical zero-padded [252,12] program for `action` and return its length.
/// Strict: no normalization, defaults, PASS insertion, clipping or key synthesis.
pub fn encode(plan: &GrammarPlan, action: &serde_json::Value, out: &mut [i64])
    -> Result<i64, String>;
```

Admission: `out.len() == TOKENS_PER_SEAT` (checked before writing); the object has exactly the keys `farmer`, `hands`, `market` (missing or extra keys reject); `hands.len() == actors - 1`; every unit command is a nonempty array of the exact §4 arity with a supported uppercase name and item, and a JSON integer quantity in 1–1023 (transfers only); `market.len() <= order_limit`; every market entry is `[]` (EMPTY) or an exact §4 command with a JSON integer quantity in 0–1023; `null`, non-arrays, floats, strings as numbers, lowercase names and unit kind NONE reject. After building the tokens, `encode` runs them through the same `State` walk as `decode` (so HIRE capacity `A+h<H` and every support rule come from one implementation) and only then writes `out`; on error `out` is unchanged. Errors name the field, index and rule, with stable prefixes matching the reference codec's rejection categories (`unknown market command`, `unsupported unit command arguments`, `market item syntax`, `extra hand commands`, `market queue limit`, `quantity range`, plus `hire capacity`) so Task 5.1 can reproduce its admission table (`briefs/5.1-bc-data.md:185–199`). Round-trip law: for every admitted program `t`, `encode(decode(t)) == t`; for every admitted action `a`, `decode(encode(a)) == a`. Task 1.4/1.5 expose it as a PyO3 function over a caller-owned `int64 [252,12]` row; no JSON string hot path.

**Live/inactive boundary:** all native observations are live under v4 auto-reset (`W:docs/kaggriculture-contract.md:166`). Thus native `decode` rejects length 0. H:63–68 permits all-zero, length-0 **synthetic inactive model rows**; Task 2.3 handles those without calling native decode. Do not add an implicit PASS interpretation or let native step use an untrusted live flag (open question 3).

## 4. Semantics

### State machine per slot

Use the compact future-mask state in `R:engine_rs/src/myolie_sampler.rs:113–265`. Let `u` be completed units, `p` submitted market orders, `h` submitted HIREs before the frame, `A=actors`, `O=order_limit`, `H=hire_limit`, `ready=(u==A)`. All slots first reject negative/out-of-width tokens. All transitions below occur only after admission. `δ0` means singleton zero; state does not retain item/digit values after their support effect ends (the input frame retains them for rendering).

| Slot | `allows` after vocabulary bounds | `advance` |
|---|---|---|
| 0 `unit_actor` | `{u}` until ready, else `{0}` | No semantic change; next slot. |
| 1 `unit_kind` | `1..18` until ready, else `{0}` | 0→None; 6/7→Transfer; 8→Plant; other admitted kinds→Ordinary. |
| 2 `unit_target` | `{0}` always | No semantic change. Width 128 is reserved, not spatial targeting. |
| 3 `unit_item` | Transfer: `1..12`; Plant: `1..5`; otherwise `{0}` | Plant becomes Ordinary after validating its item. |
| 4 `unit_quantity_present` | Transfer: `{0,1}`; otherwise `{0}` | Save present; absent Transfer becomes Ordinary. |
| 5 `unit_quantity_high` | Present: `0..31`; otherwise `{0}` | `quantity_high_zero = present && token==0`. |
| 6 `unit_quantity` | Absent: `{0}`; present/high=0: `1..31`; present/high>0: `0..31` | Clear quantity flags; Transfer becomes Ordinary. |
| 7 `market_kind` | If ready, unit None and `p<O`: `0..7`, removing HIRE unless `A+h<H`; otherwise `{0}` | 0→None, 1→Hire, 3→Seed, 4→Product, 5→Animal, 6→Sell, 2/7→Other. |
| 8 `market_item` | Seed: `1..5`; Product: `{1,9}`; Animal: `10..12`; Sell: `1..9`; otherwise `{0}` | Product/Animal/Sell become Seed, a shared quantity-bearing phase. |
| 9 `market_quantity_high` | Seed: `0..31`; otherwise `{0}` | No semantic change. |
| 10 `market_quantity` | Seed: `0..31`; otherwise `{0}` | Seed becomes Other. |
| 11 `stop` | `{1}` iff ready, unit None and market None; otherwise `{0}` | 1→terminal `None`; 0→new frame with `u += unit!=None`, `p += market!=None`, `h += market==Hire`; reset slot and local flags/phases. |

The support-only phase `Seed` after market item does **not** change the decoded kind: use the original typed frame's kind for its command. Sources: `R:engine_rs/src/myolie_sampler.rs:147–258`; H:43–52. This detail prevents incorrectly forcing quantities for only BUY_SEED while masking BUY_PRODUCT/BUY_ANIMAL/SELL.

### HIRE, STOP, NONE and EMPTY

The exact inequality is **`A + exclusive_prefix_submitted_HIREs(p) < H`** at an available market slot, with default `H=241`. The increment happens at the end of the admitted HIRE frame, even if the kernel later cannot afford it. No cash, forecast, opponent identity or execution outcome enters grammar state. Inductively, after an admitted HIRE `A+h <= H <= 241`; if `A==241`, no HIRE is admitted. When `H<A`, zero HIREs are admitted although the existing actor count remains valid. Thus grammar-admitted HIREs cannot turn 241 actors into 242. The kernel performs at most one hire per HIRE order and then clears that order (`W:engine_rs/src/lib.rs:4004–4022`); day reset may reduce actors, which does not invalidate the bound. Sources: `W:docs/kaggriculture-contract.md:212`; `R:engine_rs/src/myolie_sampler.rs:176–181,250–258`.

All A actors get a unit frame in ordinal order, including PASS. Market positions start at frame A. The **first final NONE** is the STOP frame, after all HIRE corrections in the heads; all slots are zero except `stop=1`. At `p==O`, market kind is forced NONE, ensuring the extra sentinel after a full queue. NONE at `p<O` is a sampled early STOP, retaining its slot-7 probability; the forced sentinel has zero density. Later positions have zero density and are omitted from the active program. These density rules belong to 2.3, while Rust validates the resulting final program (H:63–83). Maximum length is `241+10+1=252`.

EMPTY is market kind 7, emits **`[]`**, increments `p`, leaves HIRE count unchanged and has `stop=0`. It never shortens the queue. Structural NONE emits no JSON order. A standalone `[]` or `null` unit command is outside the canonical grammar. Sources: `W:docs/kaggriculture-contract.md:185–213`; `R:engine_rs/src/myolie_sampler.rs:349–380`.

Missing farmer defaults to PASS and missing/nonarray hands to empty (`:1521–1530`); canonical decoding never relies on these defaults. Unit nonarrays/empty arrays are ineffective, not canonical commands (`:3125` onward). PICKUP and shed PLACE default omitted quantity to 1; nonpositive requests do nothing; animal PLACE consumes one animal in its earlier branch and may ignore quantity (`:3183–3249`). Parsing/`step` success does not mean purchase, movement or profitability succeeded. Assert JSON equality and selected state effects alongside kernel acceptance, so permissive engine no-ops cannot conceal a wrong decoder.
