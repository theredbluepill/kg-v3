## Source findings and selected design

### Root placement and L4

Create `src/kaggriculture/mod.rs` and `src/kaggriculture/observe.rs` in the root crate, with supporting files below. Task 1.4's PyO3 environment must be registered in the existing `rs` cdylib. Putting C4 inside the engine would require changing the pinned module registry and still would not solve the eventual root integration. A second extension/process boundary would abandon the required caller-buffer path.

Add a root path dependency on `kaggriculture-engine`; retain `engine_rs` as a standalone package with its own lockfile, not a workspace member. **Select the L4 repair**, not feature isolation: root compilation now unifies `serde_json/arbitrary_precision` and `preserve_order`. Port the small, understood, **test-only** `fixture_float` idea from the reference into the `#[cfg(test)]` module in `src/rules_engine/generation.rs`. Deserialize the three `RandomCall::Uniform` fields through `serde_json::Number`, convert to finite f64, and leave production rules and oracle comparisons unchanged. A minimal tagged-enum decimal regression must fail after feature unification and pass after the repair; do not rely only on generated fixtures being present.

No file is added under `engine_rs/`; its manifest, checker and retained bytes therefore need no edit. If implementation changes this decision, a new engine file requires an `authored` entry **and** an explicit update/test of `verify_task_authored`, which currently permits exactly `engine_rs/tests/replay_parity.rs`. ### Public state access, ownership and cost

`Game`'s config, farms, private state and clock are private. `public_state()` clones public data only; `seat_money()` allocates a two-element `Vec` and gives no inventories. `snapshot()` calls `public_state()`, clones both private states, and allocates status/reward vectors. Consequently:

1. Keep a validated immutable config beside its `Game`, bound by a small `ObservationGame` wrapper. Its constructors receive the same `Config`/`TraceHeader` passed to the engine. Do not accept an unrelated config at every write; there is no public getter with which to verify it.
2. Snapshot **once per environment**, not once per seat. Borrow own and rival farms from the public snapshot; pass **only** `privates[seat]` to the per-seat encoder. Both privates necessarily exist inside native snapshot memory, but the other private state never enters that row's field calculations.
3. No JSON serialization/parsing of game state on the live write path. Configuration `PyInt`s have no public numeric getters; use their public `Display` decimal representation with checked `parse::<i64>()` once at constructor admission. Do not call private `to_f64`/`capped_usize` or add accessors to vendored bytes.
4. Snapshot cost is O(public tiles + actors + private keys), including heap allocations for strings/JSON maps and both inventories. Output storage is O(E) and allocated once by the caller; those are separate claims. `PreparedObservation` keeps the snapshot only through the write, never between turns as policy memory.
5. Measure snapshot-only, validation-only on an existing snapshot, write-only on an already prepared observation, and complete snapshot+validation+both-seat-write separately, at sparse and 241+241 actors. Factor a private `validate_snapshot(snapshot: &StepSnapshot, config: &ObservationConfig) -> Result<(), ObserveError>` seam used by `prepare()` and the timing test; do not call a prepared write a validation measurement. Use 20 warmups and 200 timed repetitions with one game, preallocated output/staging, one CPU thread, `black_box`, and record total wall time, ns/env, ns/seat, bytes written, source/config/corpus hashes, build profile, CPU and thread count. Stop at two minutes/1 GB. No optimizer or model. Report component costs without a learner-throughput claim.
6. Reopen the access path if measured snapshot/validation work dominates native preparation at Task 1.4/6.1's representative workload or prevents the complete-work throughput target once measured. A separately reviewed upstream/pinned-engine read-view API is a possible future change; do not silently add it here. No invented latency acceptance threshold.

### Configuration and numeric admission

Construction checks: board size exactly 10; two farms; positive `episodeSteps`, `turnsPerDay`, `shedCapacity` and three town intervals; nonnegative `startingMoney` and `farmHandCostMult`; numeric nonnegative finite `weedSpawnChance`; orders in 1..10; checked `turnsPerDay * orders <= 240`; `marketParams == {}`; extra keys only `actTimeout`, `runTimeout`, `seed`. The framework extras are not encoded and never replace the environment seed. Confirm these scalar JSON-schema ranges against the pinned official schema when implementing; disagreement is question Q4, not permission to narrow the accepted contract.

All exact config integers must parse to i64 without a float intermediate (`startingMoney = 2^63` fails). Integer JSON tile/market values must have an integer representation and fit i64: reject `1.5`, strings, bools, out-of-range values and float-valued `1.0` for the exact market channels. No approximate-integral tolerance. Native i64 counts retain their bits, including values beyond f32's exact-integer range. Counts are nonnegative as required by the Task 2.1 schema; date/deadline sentinels permit -1 only where applicable. Float32 channels use f64 arithmetic then a single cast and check **both** f64 and f32 finiteness; finite f64 can overflow f32. Banks remain finite f64. Large finite scaled values are accepted, never clamped to [0,1] or [-4,4].

Per observation validate complete board shape, coordinate pair length and x/y in 0..9, exactly one inventory per own actor, 1..241 actors/farm, <=8 shops, enum/key vocabularies, quadrant membership/uniqueness, required applicable tile fields, all conversions and every derived value. Unknown items must fail rather than disappear from fixed tensors. Both seats are preflighted before either is published. For imported state, reject nonempty `public.market.params` (it can override defaults even when config `marketParams` is empty); absent/empty uses defaults. Validate clock agreement with config: public day/hour must equal step division/remainder. `Game::from_header` recomputes them, so the oracle reader also checks the input header before construction.

Use checked usize products for shapes and offsets, and i128 for subtracting two i64 dates and summing the 12 shed counts. Shed room is the engine's nonnegative capacity remainder, `max(0, capacity - sum(shed))`; it is not a signed overdraft. Keep intermediate sums wide instead of overflowing an i64 or rejecting a large **finite** scaled field. Imported sums outside the engine's safe transition arithmetic need explicit Task 1.4 admission treatment (Q4); observation encodability alone does not certify stepping that state.

**Hire channel:** engine `do_hire` computes `BigInt(mult) * fib(hires_today)`, where `fib(0)=1`, `fib(1)=1` and each iteration `(a,b)=(b,a+b)`. Rebuild this small public-rule formula in `config.rs`, with direct `num-bigint` and `num-traits` dependencies, not engine edits or floating recurrence. Convert exact cost to f64, divide by 200,000, cast once to f32. Compute for each player token using that farm's **public** `hires_today`; rival cost is not copied from self. At config admission, precompute the finite scaled-cost prefix for positive multipliers, stopping at the first f32 overflow (Fibonacci is monotone); store the last supported hire index. A later index fails with `player_features[role,10]` and the hire count. For multiplier zero, return exactly zero for every representable hire count without iterating to that count. Do not reject a config merely because an unobserved hypothetical hire count could overflow. For dense fixtures with 240 hires use zero multiplier; test positive-multiplier overflow separately. Literal costs for hires 0..5 are `[m,m,2m,3m,5m,8m]`.

## Field-by-field write contract

All fields have `[E,2]` leading axes, contiguous C layout, with row index `2*env+seat`. Every successful write fully overwrites every field, including padding. Set output rows to positive zero/false first. Enum index zero is safe padding **and can be a real category**; mask alone determines presence.

Pinned orders: TileKind `[EMPTY,LOCKED,WEED,PLANT,COOP,PASTURE]`; Crop `[NONE,WHEAT,CARROT,TOMATO,STRAWBERRY,MELON]`; Animal `[NONE,GOOSE,COW,SHEEP]`; Item `[WHEAT,CARROT,TOMATO,STRAWBERRY,MELON,EGG,MILK,WOOL,FERTILIZER,GOOSE,COW,SHEEP]`; Product first nine Items; ShopType `[BAKERY,BRUNCH_SPOT,FARMERS_MARKET,ICE_CREAM_SHOP,PET_CAFE,PIZZA_SHOP,SMOOTHIE_SHOP,YARN_STORE]`. `SORTED_SHOPS` is private in the engine: pin these eight contract strings in v3 and check the reference outputs. CROP_NAMES/ANIMAL_NAMES/PRODUCTS are public and should be cross-checked directly.

### Globals and masks: five tensors

`global_features` f32 [15]: `[step/Ep, hour/D, day/(Ep/D), max(0,max(1,Ep-1)-step)/Ep, D/24, M/10, C/1000, mult/100, Ep/1000, weed_chance, unlock_interval/D, shop_sell_interval/D, center_sell_interval/D, starting_money/200000, shop_count/8]`. Ep/D is f64 division, not integer division and **not** the legacy `max(1,Ep/D)` denominator. Use wide subtraction for remaining transitions.

`globals_int` i64 [16]: `[step, day, hour, Ep, D, M, C, mult, unlock_interval, shop_sell_interval, center_sell_interval, starting_money, own_hires, rival_hires, own_actor_count, rival_actor_count]`.

`still_playing` bool scalar: true for each returned row, including explicit-state observation encoding. Task 1.4 must reset completed games **before** encoding the live observation; transition done/banks have separate buffers. Do not derive this from `snapshot.done` or action availability.

`order_limits` i64 scalar: M=`config.max_market_orders_per_turn`. Evidence: `Game::process_market` reads that config, takes `orders.iter().take(max_orders)` for each submitted queue and processes those slots. There is no per-day decrement or subtraction of hires/cash/actor count. The 241-actor grammar hire cap is separate. In-envelope observations have 1..10; the schema permits zero for synthetic contexts, but live engine encoding never invents it.

`action_mask.can_act` bool [252]: for f=0..251, `f < own_actor_count + M + 1`. Use checked addition. One actor and M=3 produces five true frames (actor, three possible orders, STOP). At 241 actors and M=10 all 252 are true. This is a potential-frame mask, not affordability or prefix-dependent vocabulary legality.
