# Local checks of the 8-rank run package (Mac, CPU, 2026-09-30)

These checks exercise the scripts' logic on the Mac only. No GPU, pod, torchrun or live W&B call was involved. The GPU paths of `setup.sh`, `qualify.sh`, `launch.sh`, `check_flash_all_gpus.py` and `allreduce_bench.py` are unexecuted.

- **Seed probe.** `uv run --no-sync python ops/rebuild-2026-09-29/8rank-run/seed_probe.py configs/kaggriculture_8rank_bc_finetune.yaml --world-size 8` exited 0 with a 304 MB peak RSS. It found 256 distinct construction seeds and base seed 0: rank r held seeds r, r + 8, …, r + 248, with next seed r + 256, and no violation (`local-seed-probe.json`). The first attempt failed because `run_ppo`, loaded by path, was not registered in `sys.modules` before its dataclasses ran; the fix registers it first.
- **Watchdog.**
  - `watchdog.py --self-test` passed: two low banks separated by a normal one do not stop; two consecutive game intervals below 20,000 do; an evaluation row with `eval/promoted` 0 never stops; NaN, inf, `"NaN"` and `"-Infinity"` stop; nonfinite `_`-prefixed system fields are ignored.
  - Scenario runs with a fake `wandb.Api` against a real process group (`sleep`), a scratch run directory with `attempts.jsonl` and two 3 MB checkpoint files, and a scratch durable directory:
    - (a) a NaN metric row: the watchdog wrote `watchdog_stop.json`, sent SIGTERM (child status −15) and exited 3;
    - (b) healthy rows with a failed promotion: no stop, exit 0 once the group ended;
    - (c) two low-bank game intervals: a stop with the reason naming both.
  - In all three the watchdog copied both checkpoints, `checkpoint_last_best.pt` under a hash-suffixed name, and wrote `checkpoints.sha256`.
  - The first scenario run exposed a defect. Stop handling sat inside the W&B read's `try`, so a signalling error (EPERM from `killpg` on a macOS zombie group) was logged as a telemetry outage and the loop continued. Stop handling now runs outside that block, and a refused probe of our own group counts as ended.
- **Summarizer.** `summarize_run.py` against a fake 13-iteration history gave 12 complete iterations after the first, deltas of 16,384 env steps and 16 optimizer steps, SPS computed from `_timestamp`, one game-interval bank and one evaluation row.
- **Shell and lint.** `bash -n` passes for all seven shell scripts. `uvx ruff format` and `uvx ruff check --select E,F,W,I,B --ignore E501` pass on the five Python files. `ops/` is outside `just prepare`'s lint scope, so these were run by hand. No `shellcheck` is installed.
- **Durable BC copy.** `/tmp/kg-v3-bc-best/` was copied to `/Users/poonszesen/kg-v3-runs/bc-best/`. The SHA-256 lists of both trees (7 files) are identical; see `README.md`.

## r1 fixes (after `ops/rebuild-2026-09-29/codex/claude-verify-8rank-prep-r1.md`, APPROVE WITH EDITS)

Mac only, as above; nothing ran on a GPU, torchrun, nsys or a pod.

- **F2, checkpoint hash lists.** `kg_post` now writes `checkpoints_final.sha256` with paths relative to `OUT_DIR` and leaves the watchdog's append-only `checkpoints.sha256` alone. `pull_from_pod.sh` checks both lists, checks every recorded `checkpoint_last_best.pt` version against its hash-named copy, keeps the newest line for other paths, and prints `verified N / mismatched M / missing K` per list. A mismatch fails the pull; in the final pull (no interval) a missing file or a missing watchdog list also fails it. `local-pull-check.sh` (a fake `rsync` over scratch directories) gave (`local-pull-check.out`): no list yet, final mode → exit 1; clean first pull → verified 2, exit 0; clean final pull with two `last_best` versions and the final list → verified 3 and 3, exit 0; a wrong digest in the watchdog list → mismatched 1, exit 1; a pod file changed after the final list → mismatched 1, exit 1; a `last_best` version never pulled → missing 1, exit 1, and in interval mode reported with the loop continuing; a superseded digest for a rewritten non-`last_best` path → verified, exit 0. The kg_post line format was simulated with `shasum -a 256` (no `sha256sum` on the Mac), which prints the same `digest  path` layout.
- **Defect found by that harness.** `pull_from_pod.sh` used `cp -n` for the hash-named `last_best` copy. macOS's `cp -n` exits 1 when the target exists (checked on macOS 26.4: `cp -n a b` with `b` present exits 1). With `set -e` and `pipefail`, a pull outside the interval loop's `||` (the final pull, and the first pull of an interval run) therefore exited 1 without output, before verification, whenever the current `last_best` version's hash-named copy already existed. Inside the loop errexit is off, so later pulls were unaffected. It now tests for the target and copies only when absent.
- **F1, nsys.** `qualify.sh complete-work … nsys` adds `--kill=none`, adds `--wait=all` only when `nsys profile --help` lists `--wait`, saves that help text as a receipt, and stops before launch if the help has no `--kill`. `bash -n` passes; no nsys exists on the Mac, so the capture's behavior is unexecuted.
- **Watchdog.** `wandb_run_path` raises `ValueError` on an `attempts.jsonl` with no line, which the watch loop already treats as "cannot resolve yet, retry"; a partial line raises `JSONDecodeError`, also a `ValueError`. `watchdog.py --self-test` now covers both and passed; with the guard removed it fails with `IndexError` (`mutations.log`, W1).
- **Other P3s.** `qualify.sh threads-sweep` skips 8 threads when `nproc` < 72; `allreduce` now runs `kg_preflight`; `launch.sh` refuses to run with job control on, which is the one case where `setsid` would fork and `$!` would not be the process group; `summarize_run.py` reports `seat_rows_per_second` in place of `learner_seat_sps` and drops the BC-only `perf/learner_seat_rows_per_second` column. The summarizer against a fake 13-iteration W&B history gave 12 iterations, 196,608 env steps in 48 s, 4,096 env steps/s and 8,192 seat rows/s, deltas 16,384 and 16, one game-interval bank and one evaluation.
- **Mutations.** The four config mutations were rerun with the command recorded (`uv run --no-sync pytest -q -p no:cacheprovider tests/kaggriculture/test_configs.py`, 78 passed unmutated); each failed the same tests as before (`mutations.log`).
- **Lint.** `bash -n` on all shell scripts; `uvx ruff format` and `uvx ruff check --select E,F,W,I,B --ignore E501` on the Python files.
