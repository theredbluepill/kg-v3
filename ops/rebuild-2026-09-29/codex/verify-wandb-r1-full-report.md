**Findings**

1. **P2 — The credential-copy workflow can forward unrelated credentials.** `cookbook/workflows/install-the-wandb-credential-before-any-pod-launch.md:20` and `:28`. Netrc entries are token-based, but the awk filter assumes line boundaries. A valid synthetic line containing the W&B entry followed by another `machine` entry, or by `default`, forwards both passwords. The suggested grep count still reports one W&B header. A valid split `machine`/hostname layout extracts nothing. Ordinary one-entry-per-line and multiline layouts work. Fix: parse netrc, select the exact `hosts['api.wandb.ai']` entry without default fallback, serialize only that entry safely to SSH stdin, and fail before installing when extraction is empty. Test packed entries, defaults, and split tokens. The local simulation confirms that the existing install body otherwise refuses a second overwrite, preserves bytes, and sets mode 600; the key is not placed on argv or printed.

2. **P2 — Some invalid settings bypass the early gate and fail only during W&B initialization.** `python/owl/train/logging.py:87`, `:135`, `:174`. With installed W&B 0.26.1: (a) `WANDB_MODE=''` passes the gate but SDK environment-settings validation rejects it before the explicit init-mode override; (b) a whitespace-only environment API key plus a valid synthetic netrc passes via netrc, but the SDK rejects the environment key rather than falling back; (c) a nonempty environment key bypasses base-URL validation, so a missing-scheme URL passes this gate and fails later. Model/env/trainer work precedes logger initialization. Fix: distinguish absent from present-but-empty mode, reject whitespace API keys with a sanitized actionable error, and validate the base URL before returning an environment credential source. Add hermetic SDK-settings/auth regression cases. This finding concerns predictable local configuration errors, not remote validity of a syntactically valid key.

3. **P2 — “Strict schema” receipts accept malformed values and inconsistent identities.** `python/owl/train/logging.py:315` and `:277`. `read_attempts` checks exact keys and loose equality of the attempt number, but accepts `attempt=false`, a list-valued experiment ID, an unknown telemetry mode, and a null config hash. It also accepts a second record with a different experiment ID. `plan_attempt` stringifies malformed persisted IDs instead of rejecting them. Five independent negative tests fail against unchanged HEAD. Fix: validate types and permitted values, exclude bool as an integer attempt, validate persisted experiment IDs, validate the telemetry enum and hash, and enforce stable experiment/job identity and source-chain consistency across receipts. Reject malformed persisted data before planning a resume.

4. **P2 — Credential-bearing URLs can leak through exception messages.** `python/owl/train/logging.py:115` and `:175`. `_wandb_host` returns `.netloc`, including userinfo. With a synthetic URL containing username/password, the missing-credential error contains the synthetic password. `:177` also quotes a malformed URL verbatim. Distributed exception handling can put these messages on stderr. Fix: reject URL userinfo without echoing it, avoid quoting raw URLs, and expose only a validated hostname/port. Add synthetic-marker assertions against both exception text and rendered tracebacks. The malformed-netrc token suppression itself is correct and mutation-tested; ordinary env keys are not added to receipts or logger config.

5. **P3 — Two promised invariants have gaps in repository test coverage.** `tests/owl/train/test_logging.py:250` and `tests/scripts/test_run_ppo.py:3534`. Deleting the attempt-order check survives all 21 logging tests. Inserting an actual `FullConfig.from_file` before the telemetry gate survives all 112 run_ppo tests (one skipped): the current fail-fast test watches `_log_cli_overrides`, not the config read. Fix: add a malformed-order receipt test and make `FullConfig.from_file` itself fail if called before the missing-credential gate. Independent scratch tests pass on HEAD and kill both mutants. No product code was extended.

6. **P3 — Document the offline-to-online resume precondition.** `README.md:390`, `python/owl/train/logging.py:439`, and `cookbook/workflows/install-the-wandb-credential-before-any-pod-launch.md:62`. Generic resume defaults online and correctly preserves `id=old_id, resume='must'`. A never-synced offline run has no remote run, so this fails. Installed SDK source and a local sender/API double confirm the missing-run error without network; SDK source also warns that offline resume does not resume a remote run. Fix: document and test sync-before-online-resume and the deliberate offline-continuation procedure. Keep strict `must` behavior for established remote runs. This is an unsupported/documentation edge, not a reason to silently create a replacement online run.

7. **P3 — The audit overstates the Slurm gate timing and omits wrapper names.** `ops/rebuild-2026-09-29/wandb-audit.md:14`. The credential guard runs inside the submitted sbatch job after allocation, before container/trainer startup; it is not “before sbatch work.” The three `launch_*experiment`/scaling wrappers submit first and are not explicitly inventoried; `launch-interactive.sh` is also omitted, though it only opens a shell. Fix: group/list these wrappers and describe the actual timing. No additional v3 training launcher was found in the requested integration scope.
