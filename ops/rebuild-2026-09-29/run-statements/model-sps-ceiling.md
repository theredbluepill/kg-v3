# Run statement — model-only SPS ceiling probe (COMPONENT measurement, single GPU, ≤ 45 min)

**Label: component measurement.** This probe times only the model's share of one PPO update. It gives an upper bound on env steps/s *if the engine, host copies, GAE, logging and DDP cost nothing*. It does **not** measure or prove end-to-end SPS (CLAUDE.md throughput rule), and every result derived from it is labeled that way.

- **Question (diagnostic, not training):** at the preset model (`configs/model/kaggriculture.yaml`: width 256, depth 8, 8 heads, `force_flash_attn: true`) with the heads merged (Task 2.3), what is the per-update model wall time on one RTX PRO 6000 Blackwell, and which workload dominates it? From that, what model-only SPS ceiling per rank follows, and what time budget per env step is left for the engine before it becomes the bottleneck?
- **Workloads** (GPU 0 only; fp32 params under `torch.autocast(bfloat16)`, TF32 on via `owl.train.utils.configure_torch`, trunk compiled via `compile_transformer_trunk(mode="max-autotune-no-cudagraphs")` (dynamic=True), heads eager; synthetic contract-valid observations from `tests/kaggriculture/conftest.py::make_obs` for 128 envs, tiled along the env dim for larger batches; synthetic `expected_grammar_tables`):
  - **(A) rollout sampling:** `model(obs)` (sample actions + values), 256 rows (128 envs × 2 seats), `no_grad`.
  - **(B) PPO train step:** `evaluate_actions` on 1,024 rows (spm 8 × horizon 64 × 2 seats) with actions sampled in (A), a PPO-shaped loss (clipped ratio 0.2 + 0.5·value MSE − 0.01·entropy), backward, `clip_grad_norm_(10)`, `create_optimizer(MuonConfig())` step.
  - **(C) teacher precompute:** the Kaggriculture model has no `compute_teacher_distillation_targets`, so the proxy is `evaluate_actions` under `no_grad` over one rollout, 16,384 rows (128 × 64 × 2), which goes through the chunked packed trunk path and the head row chunks. This is a proxy for the future last-best-teacher forward, not that code path.
  - **(D) critic bootstrap:** `compute_value` on 256 rows, `no_grad`.
  - **Densities** (same for all 128 envs; tokens per row = own + rival actors + shops + 219 fixed): sparse (1 own, 1 rival, 1 shop → 222 tokens), mid (40 own, 40 rival, 4 shops → 303 tokens), dense (241 own, 241 rival, 8 shops → 709 tokens, the padded maximum). One process per density, order sparse → mid → dense, sharing one run-local Inductor cache (so later processes may pay less compile time; reported as such).
- **Method:** per workload: first call timed separately with `perf_counter` + `synchronize` (includes compile/autotune), then ≥ 5 warmup iterations, then 20 timed iterations bracketed by CUDA events; report median and p90 (and host wall median). Peak memory per workload via `torch.cuda.reset_peak_memory_stats` / `max_memory_allocated` (and reserved) against 96 GB and the 85 % rule. Counting wrappers on `owl.model.kaggriculture.use_flash_attn` and `pack_sequence` confirm the packed flash path ran and count trunk chunks per call (expected in (C): sparse 1 (padded bound 16,384 × 222 × 512 < 2³¹), mid 2, dense 3; head chunks 2 (11,096 rows per head chunk)).
- **Derived ceiling (written formula):** env steps per update per rank = 128 × 64 = 8,192; update wall = 64·t_A + t_C + 16·t_B + t_D (one PPO epoch of 16 minibatches); ceiling SPS per rank = 8,192 / update wall; two ranks ≈ 2× (the DDP all-reduce of ≈ 6.25 M params is **assumed** small and is not measured).
- **Expected discriminating observation:** (B) × 16 or (A) × 64 dominates update wall at dense density; if (C) dominates, the teacher precompute becomes the target. If `use_flash_attn` is false anywhere or the chunk counts differ from the expectation above, the path is not the one described and the timing is reported as not representative.

## Post-run addendum (2026-09-29, after Codex review `../codex/verify-sps-ceiling-r1.md`, APPROVE WITH EDITS)

The pre-run text above is unchanged as committed in `ed61770`. The following statements correct or qualify it against the retained receipts in `../model-sps-ceiling-2026-09-29/`.

- **Scope of the result.** The derived "ceiling" is a **conditional estimate for the specified A/B/C/D synthetic schedule**, not a proven bound: B (PPO-shaped loss) and C (teacher proxy) are surrogate workloads. The script retained no finite-loss/gradient check and no sampling-versus-replay equality check, so the result is **timing evidence only**. At `e1458d2`, `configure_model_compile` with `model_compile="trunk"` still rejects the Kaggriculture model; the probe called `compile_transformer_trunk` directly.
- **Safety line vs receipt.** The pre-check line above says 0 MiB / 0 % at 06:41:21Z. The prelaunch capture (`pod/receipts/idle_nvidia_smi_prelaunch.txt`, 06:45:04Z) shows **563 MiB on both GPUs**, 0 % utilization and no running compute processes. Launch followed at 06:45:05Z without the wait that the "if GPU memory is in use" rule called for.
- **Stopping condition vs driver.** `pod/run_all.sh` (no `set -e`, one `timeout 1500` per density) did **not** enforce the first-failure stop or the 45-minute aggregate limit; it would have continued past a failure and allowed up to 75 min. All three densities exited 0 in **227 s** (06:45:05Z–06:48:52Z, `pod/driver.log`), so the gap did not affect results.
- **nsys.** The `nsys` pre-check above is **operator-reported**; no command-output receipt of it was retained.
- **Memory rule.** The 85 % rule (plan, "Resource fit") is on `max_memory_allocated`; the allocated peak was 40.275 GiB (dense B), within it. The reserved peak, 84.994 GiB (89.5 %, dense C), is a separate observation; its carryover/fragmentation explanation is an untested hypothesis.
- **Chunk expectation.** Trunk chunks in C were counted and matched (1/2/3). The sparse bound quoted above as "padded" is the **packed**-token bound (3,637,248 × 512 < 2³¹). The 2 head chunks were calculated from source (`head_rows_per_chunk`), not counted.
- **Method wording.** B's "clipped ratio" is one scalar joint ratio per row; each row is one seat, so it is per-player joint clipping. Host/event timing agreement cannot establish intrinsic synchronization because the timer synchronizes on the end event before reading the host clock. A − D is incremental sampling-path cost, not isolated head kernels.
