## Checks

**1. fp32 discriminating check** (`c1_fp32_ref.py`; `results.md` "Phase 6.0" (b) open item: 0.017–0.021 % of trunk elements outside `0.02 + 0.02|ref|`).
- *Question:* is that residual BF16 rounding common to every BF16 path, or specific to one path?
- *Method:* per density (mid, dense, mixed; 128 envs = 256 rows), same weights, one input `x_bf = _assemble_tokens(obs).to(bf16)`. Reference: `_forward_transformer_trunk(x_bf.float(), mask, None)` with autocast off, TF32 off, padded SDPA forced to the MATH backend (32-row chunks); an auto-backend fp32 run gives the reference's own noise floor. BF16 paths: **compiled** (`_run_trunk`, packed flash, compiled trunk), **eager** (same, compiled callable removed), **padded** (`_forward_transformer_trunk(x_bf, mask, None)`, eager padded SDPA). Per path vs fp32 on present tokens: max/mean/RMS |Δ|, count and fraction outside `0.02 + 0.02|ref|`, error in BF16 ulps of the reference, breakdown by |ref| bucket and token group, top outlier channels, the 32 worst elements (row, token, channel, group, row length, ref, value, Δ), every outlier coordinate (capped at 50,000 per path; retained in `*.outliers.json`), pairwise outlier-set Jaccard, and the Phase 6.0 pairwise comparisons. Two processes: compiled under ATEN-only (`c1_aten`) and under default backends (`c1_default`, the Phase 6.0 setting); eager/padded/reference repeat in both.
- *Discriminating observation (pre-declared rule):* a path is **path-specific** if its mean |Δ| or its outside-tol fraction vs fp32 exceeds **2× the median of the three paths**; otherwise the three are **similar**, which supports BF16 rounding. Outliers concentrated at large |ref| and shared across paths also support rounding; one path's outliers concentrated in a token group, channel or row set indicate a path-specific error.
- *Pass (for the stopping rule):* exit 0, 3 density results, finite reference and outputs, exactly one pack call of all present tokens and `use_flash_attn` true for compiled and eager. The numerical comparison is the result, not a pass criterion.

Random BF16 `x` (requires grad) and fixed random BF16 `g`; `loss = sum(out * g)`; backward. Compiled vs eager: output, input gradient dX, every parameter gradient. A second eager run gives the eager-vs-eager floor (flash-attn backward is not bitwise deterministic). **Deviation: depth 1** (one real `TransformerBlock` + final norm at preset width/heads/MLP, compiled through the registered path). ## Amendment 1 — attempt 2 (written after attempt 1 stopped, before relaunch)

**Attempt 1 (09:15:32–09:16:28Z, driver 55.4 s, exit 3; artifacts `gpu-checks-2026-09-29/pod/attempt1/`).** `c3_mid_aten` passed. `c2_aten_bwd` ran every point, and the driver stopped there as the stopping rule requires: the running `c3_dense_aten` was terminated (rc −15) and nothing else started. The only failed criterion was `blocks.0.attn.k.bias`, with gradient `max|Δ|/max|ref|` of 1.155 (warm `dense:8`, **below** the bound), 0.807 (4,194,305) and 0.858 (4,198,400). Everything else passed with wide margins at both targets: a single trunk call of all packed tokens; output 0 wrong tokens, max |Δ| ≤ 0.034; dX rel_max ≤ 0.0087, 0 tokens > 0.5, 0 non-finite, 0 at masked tokens; every other parameter gradient rel_max ≤ 0.0142. Attempt 1 is recorded as it stands: it is a stop on criterion `attn.k.bias`.

**Diagnosis (information error in the criterion, not a kernel error).** The key bias adds `q_i·b_k` to every logit of query `i`, a constant across keys, and softmax is invariant to that shift. So ∂L/∂b_k ≡ 0 analytically, and both compiled and eager values are rounding residue. A relative error against ~0 is undefined, which is why it fails equally below the bound. Independent check (local CPU, `post-run/kbias_analytic_zero_cpu_check.txt`, depth-1 preset trunk, 4 rows): fp64 max|g k.bias| = 3.9e-14 vs max|g q.bias| = 30.8 (ratio 1.3e-15); fp32 ratio 7.6e-7; BF16 autocast ratio 5.8e-3.

**Change (only this criterion; everything else unchanged).** For `attn.k.bias`, the relative-to-itself criterion is replaced by: 0 non-finite and max(max|Δ|, max|compiled|, max|eager|) ≤ **0.05 × max|eager grad of the same block's `attn.q.bias`|**. The CPU BF16 residue ratio is 5.8e-3, so the bound leaves about 9× headroom, while a corrupted, O(1) gradient would exceed it. `c2_trunk_bwd.py` now also records `max_abs_diff`, `ref_max_abs` and `out_max_abs` per parameter (sha256 `12b46fd7…`; the comparisons are unchanged). `driver.py` (`15b41c74…`) applies the amended rule. `launch.sh` (`32d69f31…`) uses `timeout -k 20 3540`, so the aggregate driver wall stays ≤ 60 min (attempt 1 used 55.4 s). The internal deadline stays 55 min. Other scripts are unchanged.
