# Run statement — ATEN-only GEMM backend A/B (correctness above the int32 bound + component timing), single GPU, ≤ 45 min

**Label: infrastructure diagnostic.** This run changes one Inductor setting, `torch._inductor.config.max_autotune_gemm_backends`, from torch 2.9.0's default `"ATEN,TRITON,CPP"` to `"ATEN"`. It changes no model, loss, reward or learning code. Adopting it would be an **infrastructure deviation from Isaiah's default backends**, not a learning change. The timing half is a **component measurement conditional on the A/B/C/D synthetic schedule** of `model-sps-ceiling.md`, not end-to-end SPS.

- **Question (owner):** can v3 be made immune to the torch 2.9 compiled-GEMM int32 overflow (`cookbook/references/compiled-gemm-template-overflows-above-2-21-rows.md`; `results.md` "GEMM limits at our shapes")? **Hypothesis:** with `max_autotune_gemm_backends = "ATEN"`, every compiled mm/addmm lowers to extern cuBLAS (`extern_kernels.mm/addmm/bias_addmm`, 64-bit indexing), so the vulnerable Triton mm/addmm template class (and the persistent-TMA and decompose-K templates) is never generated, while the other Inductor fusions (pointwise, norms, reductions) stay Triton.
